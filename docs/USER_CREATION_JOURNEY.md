# Moirai Cut 真实用户创作链路

更新时间：2026-08-02

## 结论

当前产品已经具备完整剪辑引擎和 Agent 原子能力，用户可以在同一工程中导入素材、选择上下文、让 Agent 修改、人工微调、预览并导出。此前最大的体验断点不是“没有能力”，而是完整能力没有被包装成一个第一次使用就能理解的任务入口。

本轮新增两层入口：

1. 编辑器智能剪辑空状态中的 **完整创作 Skill** 卡片，明确展示“理解素材 → 生成时间线 → 预览质检 → 本地导出”，无需用户知道 Skill 语法。
2. 项目级 `moirai-cut-create` Skill，把工程读取、素材 JSON、场景识别、声音分析、原子回写、revision 防冲突、视觉质检与 draft 导出固化为一次调用协议。

## 真实验证基线

- 编辑器与本地 API：`bun run agent:doctor` 得分 100/100。
- Agent 运行时：已复用本机 Codex 登录，Moirai Cut MCP 已安装。
- 当前真实工程：`地坛 × Reed｜Cinematic Director Cut V2`，验证时 revision 737。
- 当前时间线：5 条轨道、42 个可编辑元素；视频/图片、文字和音频均在真实工程状态中。
- Codex app-server：7 个模型、3 个工具档位；`skills/list` 已发现并启用 `moirai-cut-create`。
- 真实产品证据：报告使用仓库已有编辑器截图，不生成、不补绘、不替换 UI 控件。

## 用户第一次完整创作

| 用户看到的步骤    | 用户动作                 | 系统实际完成                                          | 结果是否可见                     |
| ----------------- | ------------------------ | ----------------------------------------------------- | -------------------------------- |
| 1. 打开工程       | 导入或打开已有素材工程   | 载入唯一工程文件和 revision                           | 是，素材库、预览和时间线可见     |
| 2. 进入智能剪辑   | 打开左侧 Agent 侧栏      | 连接本机 Agent 与 Moirai Cut MCP                      | 是，连接状态和工程名可见         |
| 3. 开始完整创作   | 点击“开始完整创作”       | 调用 `$moirai-cut-create`，自动读取当前工程和用户选择 | 是，流式展示最新处理步骤         |
| 4. Agent 理解素材 | 无需额外操作             | 建立 media catalog，按场景取帧、分析声音，需要时转写  | 是，分析会保存为 Agent 可读 JSON |
| 5. 生成首剪       | 等待或补充一句意图       | 带 `baseRevision` 和 `idempotencyKey` 原子写入时间线  | 是，变化直接落在共享时间线       |
| 6. 人工精修       | 拖动、裁切、改参数、撤销 | 人工操作产生新 revision，下一轮 Agent 会重新读取      | 是，始终是同一个工程             |
| 7. 预览与交付     | 播放审阅或继续对话       | lint、同步、代表帧复核、draft MP4 本地导出            | 是，返回质检结论与绝对路径       |

## 仍缺的工具或流程

### P0：开源首发前必须补

1. **全新用户浏览器 Provider 兜底验收**：没有 Codex/Claude 本地登录时，API Key 配置、连通性测试、首条消息和错误恢复必须在干净环境走通。
2. **真实 UI 最终点验**：用一个复制工程点击“开始完整创作”，确认卡片在双栏/三栏、深色模式和窄窗口中无溢出，并完成一次真实 draft 导出。
3. **跨 Agent 的项目 Skill 发现一致性**：Codex 已发现 `.agents/skills`；Claude 与其他支持 MCP 的 Agent 需要同样的一键安装与能力检查，不能只显示“已连接”。

### P1：让创作形成可复用工作流

1. **用户创作 Skill 编辑器**：在成功对话后提供“保存为 Skill”，自动提取触发语、输入参数、上下文范围、允许的工具、质量门和失败恢复；先在复制工程跑 eval，再启用到当前项目。
2. **可恢复任务中心**：场景识别、转写和导出需要跨刷新持久化 job、进度、产物与重试，避免用户把侧栏一直开着。
3. **带时间码的审阅反馈**：预览时按一个键记录当前时间码、帧和文字意见，下一轮自动成为 `opencut://` 范围引用。
4. **创作 brief 模板**：在完整创作前用四个可选字段快速限定平台比例、目标时长、叙事方向和声音策略；空着时仍可直接开始。

### P2：开源生态与专业交付

1. **Skill 库与权限说明**：展示每个 Skill 会读取什么、会修改什么、能否联网，并支持启用/停用和版本锁定。
2. **素材权利与来源字段**：让素材 catalog 保存授权、来源、署名和可发布范围，导出前做合规检查。
3. **创作效果评测集**：除了结构测试，增加匿名素材工程上的叙事、节奏、字幕和音画质量基准，避免 Skill 更新后“能跑但不好看”。
4. **一键问题包**：把项目摘要、doctor、失败 job、相关 revision 与脱敏日志打包，便于开源用户提交可复现 issue。

## “保存为 Skill”建议流程

```text
一次成功的人机协同编辑
  → 保存为 Skill
  → 自动提取触发语、参数、工具和质量门
  → 用户确认可读说明与权限
  → 在复制工程运行 3 个 eval
  → 通过后写入 .agents/skills/<name>/
  → 出现在智能剪辑的任务入口
```

这条链路的关键不是把聊天记录原样保存，而是把“什么时候触发、读取什么上下文、允许做哪些修改、怎样证明完成”固化为可测试的创作协议。
