# 模板工作台

统一时间事件可在节奏页输入，计划保留事件和每次调度的采用/拒绝依据。本体页支持复合组、
网格排列和运动跟随。工程应用区的“检查编排”先走实际编译预检；“比较方案”展示完整候选的
可执行性、分数及分项，选择后才生成待写入结果。所有检查和评分在 Rust 中执行。
MCP 对应 `preflight_template` 和 `evaluate_template_plans`，契约见 `template_schema`。
方案分数是启发式比较指标，实际写入仍重新编译并检查工程修订。

入口：`/templates`。业务规则、JSON Schema、版本保存、断句编排、声音分离与入库位于
`rust/crates/footage/src/templates/`；Web 和 MCP 只负责展示、交互与请求传输。

## 参考素材与证据

当前研究集来自开拍的 54 条公开模板预览，属于已渲染视频，不是原站的可编辑工程。
下载目录包含 MP4、封面、来源 URL、`catalog.json` 和可本地播放的 `index.html`。
`template-audit CONFIG CATALOG OUTPUT` 会逐条完整解码、测量音频并生成连续帧。
本次完整检查通过 54 条：34 条数字静音、15 条无音轨、5 条有声音。

工作台初始化了 54 份研究模板。视觉观察在 `observations.json`；具体字号、关键帧、
位置等是重建参数，未宣称恢复原站的专有模板。证据用 `observed`、`inferred`、
`authored`、`unverified` 区分，并保留参考 ID、时间范围和说明。

## JSON 本体

对象关系、语义角色与表现形式、资源槽与绑定、定义与实例的拆分见
[剪辑本体与关系](template-ontology.md)。工作台直接编辑 v2 模型，保存、编排和编译
使用同一套结构；v1 只在导入与历史读取边界转换。

`GET /api/footage/templates/schema` 返回权威 JSON Schema，包括模板和编排输入。
所有对象拒绝未知字段。顶层 schema 为 `moirai.template.v2`：

| 字段 | 用途 |
| --- | --- |
| `id`, `revision` | 稳定身份与比较交换版本 |
| `canvas` | 设计像素宽高和帧率 |
| `elements` | 独立语义角色、表现类型、媒体用途、位置策略、内容绑定、时序和动效 |
| `styles` | 字体、字号、字重、斜体、填色、描边、底色、阴影和行数 |
| `resourceSlots` | 媒体需求和说明，不含资产 ID |
| `resourceBindings` | 独立的默认槽与资产绑定；编排输入可覆盖 |
| `layouts` | 主画面区域、字幕区域、保护区域和布局模式 |
| `layoutEntrances`, `transitionRules` | 独立入场效果与前后布局关系 |
| `segmentation`, `visualRhythm`, `audioPlacement`, `mix` | 字幕、视觉、声音编排与混音策略 |
| `evidence` | 可追溯观察与创作依据 |

本体包括标题、字幕、译文、强调词、花字、人物标签、章节、列表项、数字、图标、
贴纸、箭头、下划线、圈注、底板、边框、粒子、人物描边、聚光遮罩、补充画面、
主视频、背景、音效与背景音乐。布局包括全画面、推近、圆形嵌入、分屏、画中画、
模糊填充；转场包括切换、溶解、滑动、缩放、擦除和模糊。

元素通过 `binding` 引用标题、句子、关键词、译文、说话人、固定内容或源视频。
动效由 opacity、scale、x、y、rotation、reveal 的归一化时间关键帧组成。
资源引用只接受目录 ID，不接受任意路径或可执行 URL。

## 声音分析

本地推理依赖位于 `src/templates/audio-requirements.txt`。用单独的 Python 环境安装，
通过 `MOIRAI_TEMPLATE_PYTHON` 指定解释器。默认使用用户目录下
`.moirai-cut/template-workbench/audio-env/bin/python`。首次使用 Demucs 会下载
`htdemucs` 模型；视频和音频不上传。Python 只做模型调用，候选选择、持久化、
重试队列、资源绑定校验在 Rust 中。

分离声部为 vocals、drums、bass、other。在 drums 和 other 上依据短时能量变化
提出瞬态候选，保留声音起始前 80 ms，并按尾音延长至最多 1.5 秒。
这不是专门的音效识别器；鼓点、伴奏与泄漏人声都可能进入候选。
没有明显瞬态时允许产生零个候选。

每个声音保存源混音 SHA-256、输出 SHA-256、模型设置、参考 ID、起止时间、
描述和审核版本。原始浮点 WAV 保留模型输出，包括可能超过满刻度的峰值；
`peak` 和 `rms` 是 16 kHz 单声道分析值，不能作为最终立体声响度或真峰值测量。

全部输出初始为 `review`，用户试听后选择“音效”或“背景音乐”并确认；
不适用的条目标为 `rejected`。只有确认用途匹配且文件哈希未变化的条目可以绑定。
确认操作采用版本检查，审核记录独立保留。工作台提供 WAV 试听和后台任务状态。

`clip_template_sound` 和工作台“声音来源”支持从已导入输入或声音库继续截取。
请求须且仅须提供一个 `inputId` 或 `soundId`；`startSeconds/endSeconds` 均相对
所选文件，区间须在文件内且长 0.02 至 600 秒。可从分离声部、瞬态候选或已截取
声音生成新片段，不必重新导入分离 WAV。新条目为待试听 `candidate`，不继承确认状态。

派生片段保留根 `sourceId/sourceSha256` 和原始参考中的累计起止位置，另有
`derivation` 记录父声音 ID、父文件 SHA-256 及本次相对截取区间。截取前验证父文件
哈希，截取后再次核对；重复父文件和区间返回既有条目，不覆盖名称、用途或审核版本。
首次响应回读已持久化记录，使浮点测量与重试响应一致。输出保持 44.1 kHz 双声道
float32 PCM，不附加淡入淡出、归一化或自动清洁处理。

真实参考 `reference-54-other-candidate-01`（原片 2.48–3.14 秒）截取相对
0.06–0.46 秒，派生位置为原片 2.54–2.94 秒；再截取相对 0.1–0.3 秒，位置为
2.64–2.84 秒。两次输出分别为 17,640 和 8,820 个双声道采样帧，与父 PCM 对应区间
逐字节一致。实际 MCP、工作台重试、名称审核后重试、非法来源与越界拒绝、父条目
不变均验证通过，见 `analysis/derived-sound-report.json` 和桌面/手机截图。
这两条真实派生片段仍待试听，未宣称去除了人声或伴奏；当前待试听数量因此为 76。

“分析声音”和 Agent 的 `analyze_template_sounds` 使用本地 Audio Spectrogram
Transformer（MIT AudioSet 模型）对未排除的声音分类。固定模型版本
`f826b80d28226b62986cc218e5cec390b1096902`，保存权重和特征配置 SHA-256，
无需上传媒体。声音以 16 kHz 单声道分析，窗口 10.24 秒、步长 5.12 秒，
完整覆盖每个文件；原始 527 类分数保留在本地 `templates/assessments/` 的批次结果中。

声音证据单独持久保存，不改声音的名称、用途或审核版本。接口的 `soundAssessments`
只返回音频哈希匹配的证据，包含各窗口最大标签分数、前十标签、人声与音乐分数；
`soundAssessmentJobs` 提供任务状态。相同声音集合、哈希和模型版本重试会复用任务。
人声/音乐分数达到 0.2 会提示可能含相应成分；这是排查用阈值，未经过本库校准，
不能读作百分比置信度。短于 2 秒的片段额外标记，填充到模型输入长度的短音效
可能出现偏差。低人声分数不证明没有人声；分析不能替代试听或自动确认干净音效。

本次真实批次完成 74 条：按上述阈值标记 10 条可能含人声、44 条可能含音乐，
54 条短于 2 秒，以上计数可以重叠。权重 SHA-256 为
`ae0c1e2ad4e1381d851fa9bf298ba13ebc9c5a914cdee2dbe427a6583869924d`。
这说明分离声部与瞬态候选不能直接等同于独立音效；74 条仍保持待试听状态。
真实 MCP 与工作台重复请求均复用同一完成批次，手机 390px 视口无横向溢出。

## 短句与编排

工作台“断句与编排”支持直接导入视频或 TTS 音频，在本机完成转写。导入上限为
2 GB、60 分钟，导入只写本地输入库，不触发团队 NAS 同步或云端视频分析。
Agent 可通过 `import_template_input` 导入本地路径，然后调用
`transcribe_template_input` 排队，并用 `read_template_input` 读取结果。

工作台“生成配音”和 MCP `list_template_voices` / `generate_template_speech` 可直接生成
本地 TTS。当前使用 macOS `NSSpeechSynthesizer`，通过系统结构化接口枚举稳定音色 ID；
其他平台返回不可用状态，仍可导入外部 TTS 音频。生成参数为 `name`、`text`、
`voiceId`、`speakingRate`，支持 1–2000 字符普通原文及 80–350 的系统词/分钟语速。
不支持音色克隆或系统语音控制标记。原文经 JSON 文件传给系统接口，不拼入脚本代码。

音频写为 44.1 kHz 单声道 PCM WAV，导入后自动排队进行同一套 ASR。
返回 `synthesis`（原文、音色、系统版本、输入音频 SHA-256）和 `transcriptionJob`；
生成结果不改工程，也不制造对齐时间。`read_template_input.syntheses` 保留该声音的
生成记录，工作台可展开配音原文与识别结果对照。相同请求及记录到的系统/音色身份复用
已保存音频，复用前验证音频哈希；正在运行或完成的转写任务也复用。
系统可能不提供音色资源版本，此时记录 `version: "unknown"`；缓存复用不意味着
能证明音色包从未更新或在另一台机器上重新合成相同字节。

实测同一段中文原文用婷婷音色、140/230 两档语速分别生成 10.706395/7.879456 秒声音，
各自转写出 37 个单元，测量后按默认规则编排为 4/3 句。原文中的“美业”被 ASR 识别成
“每夜”，已依据生成记录通过校正接口修正，所有实测时间和原始 ASR 保留。
WAV 完整解码、重复生成复用、语音控制标记拒绝、真实 MCP 调用、节奏分析、编排词表
保持、桌面/手机表单及同一选中素材的重复生成刷新均已验证；报告在
`analysis/tts-generation-report.json`，截图为 `tts-{desktop,mobile}.png`。
这些结果验证配音到编排的数据流程，不证明系统音色自然度或成片质量达到最终要求。

默认使用 faster-whisper 的 small 多语言模型、CPU int8、beam size 5 和 VAD。
`MOIRAI_TEMPLATE_ASR_MODEL` 可指定其他受支持模型或本地模型目录。首次使用下载模型，
之后优先离线缓存；新结果记录模型权重 SHA-256 和引擎版本。
无语音时返回空词表和 `no_speech_detected`，不会制造字幕。

原始词级文本、概率和时间全部保留。重叠或零时长单元只能合并，不能按字符数分配
虚构的子词时间；合并和小幅尾部截断会记录提示。ASR 时间仍是模型估计，
不等于人工验证过的精确强制对齐。界面提供原视频、识别字幕轨、词级核对和
“应用转写”；`correct_template_transcript` 按版本修改词的文字与理由，保持时间不变，
保留原始 ASR 和每一版校正。并发修改返回 `revision_conflict`。

输入必须有来自真实音频、ASR 或强制对齐的 `words` 时间戳：

```json
[
  {"text":"首付","start":0.1,"end":0.4,"emphasis":0},
  {"text":"30万","start":0.4,"end":0.8,"emphasis":0.8},
  {"text":"但是","start":1.2,"end":1.5,"emphasis":0.5}
]
```

规则在停顿、句末标点、说话人切换、字数或时长预算处断句，保持对齐词完整，
不按文本长度伪造子词时间。单个对齐词超过预算时给出警告。TTS 工作流应先生成
音频，再使用 TTS 返回的实测时间或强制对齐结果，不能先按字数分配时长。

当前语义匹配是可检查的中文词法规则；根据句子意图选择布局，根据词级强调值
选择关键词并绑定元素。它尚不等于大模型的上下文理解。章节起点暂以说话人或意图
变化作为边界。元素遵守互斥组、强调数量、保护区域和音效间隔；音乐不会抑制音效。
时长不足、阅读过快、资源未绑定等情况会返回警告。

编排结果的 `sounds` 保存声音库 ID、元素实例 ID、绝对起止秒数和局部时间的
`gain` 音量关键帧（dB 线性插值）。音乐按实际词时间提前压低，短暂停顿保持压低，
长停顿恢复；包络裁切到实例边界，片段从口播中间开始时不会突然恢复原音量。
`musicDuckAttackSeconds` 默认 0.08、`musicDuckReleaseSeconds` 默认 0.3；
`effectGainDb` 默认 -12。以上是可编辑的创作默认值，并非从参考音频测出的参数。
音效冷却按实际触发时间排序；该音量计划是衰减，不是 LUFS 标准化。
编译器将声音写为已有的 `library` 音轨：声音 URL 固定 ID 与 SHA-256，播放时校验文件，
不把本机端口或访问令牌写入工程。需在拥有该声音库的本地服务上预览和导出；尚未实现
跨机器携带声音文件的工程打包。音效不循环，时长取素材与编排范围的较短值；音乐按素材
时长切为独立循环片段，音量包络跨循环保持连续。循环未做节拍对齐会给出警告，
接缝仅加短淡入淡出，不能保证任意音乐都能无缝循环。音轨参与幂等标记、回读和删除检查。

声音视图支持导入本地音频或视频，并按源文件秒数截取 0.02 至 600 秒的声音。
Agent 使用 `import_template_input` 后调用 `clip_template_sound`；截取以源哈希、时间
范围和转换版本去重，不重置已有审核状态。输出为 44.1 kHz 双声道浮点 WAV，保留来源、
说明和哈希，初始为待审核，不自动宣称是独立音效。

Agent 在理解口播后可以提供 `semanticUnits`，明确语义段落、意图、完整关键词范围和
理由。所有索引基于归一化 `words`，从 0 开始，`endWord` 为不包含的终点：

```json
{
  "startWord": 0,
  "endWord": 4,
  "intent": "emphasis",
  "keyword": {"startWord": 2, "endWord": 4},
  "rationale": "保留完整名词短语，避免拆开内容价值"
}
```

非空规格必须按顺序完整覆盖所有词一次，不能重叠、遗漏或引用句外关键词。
它只改变分组和语义，不改音频时间。输出保留规格，供回读与审计。
字幕通过独立的 `captionSpans` 指定范围；留空时在语义单元内部根据停顿、标点和预算分屏。
实际研究样例 `reference-03` 已完成同音字
“每夜”到“美业”的有证据校正，并按实测模型词时间生成 8 个语义短句，
关键词包括“内容价值”“专业能力”“信任值”。

### 实测响度、音高与词间间隔

工作台的“测量口播节奏”和 MCP `analyze_template_prosody(id, transcriptRevision)`
读取输入库原音频，在 Rust 中流式测量每个对齐单元的 RMS dBFS、采样峰值、相对响度、
词前和词后间隔。FFmpeg 只负责将第一条音轨解码为 16 kHz 单声道浮点 PCM。
词间间隔来自 ASR 对齐边界，另外从音频测量连续低能量区间；未实现情绪或完整韵律分析。

方法 `aligned-rms-mcleod-quiet-v4` 保留原有响度规则，将每词响度与前后各最多四个邻词的中位数比较。
邻词须高于 -60 dBFS 且至少 40 ms，至少有两个有效邻词才提出候选。
当前词也须满足相同条件；高出中位数 3 dB 后线性增加候选权重，高出 12 dB 时为 1。
这些阈值是可审查的启发式，尚未用语义重音标注数据校准。背景音乐、音效和录音处理
都可能影响结果，响度突出不能直接等同于语义重点。

结果保存源 SHA-256、转写版本、方法、逐词测量和 `candidateWords`，不修改原转写。
重复请求读取保存结果；源文件改变或转写版本不符会拒绝请求。转写更新后旧测量不再
出现在 `read_template_input` 的 `prosody` 字段。选择“应用声学节奏候选”才将候选词表
及实测词间低能量时长送入编排，并保留文字、时间和说话人；已有人工强调值不会被候选降低。Agent 可以
用测量证据辅助语义判断，再通过 `semanticUnits` 指定完整的语义关键词范围。

真实验证：参考 03 的 54 个对齐单元产生 7 个候选，本地 TTS 的 36 个单元产生 0 个；
静音输入返回空测量。原转写完全未变，重复请求返回相同结果，错误转写版本返回 409。
工作台候选词表已传入编排，桌面 1440×1000、手机 390×844 截图均无页面错误或横向溢出。
证据保存在素材目录的 `analysis/prosody-report.json` 和 `prosody-*.png`。

音高由固定版本 `pitch-detection 0.3.0` 的 McLeod 算法在 Rust 中计算，使用完整
64 ms 窗口、10 ms 步长，窗口中心归属到原有词区间，不填补源音频边缘。
每窗去直流；只接受 65–600 Hz、周期性至少 0.85 且 RMS 高于 -50 dBFS 的结果。
`pitchSettings` 保存这些分析参数；每词 `pitch` 保存分析帧数、接受帧数和比例。
至少三个接受帧才输出 `medianHz`、`medianPeriodicity` 和 10% 到 90% 分位数的
`rangeSemitones`；词首、词尾三分之一区间各至少两帧才计算两者中位数之比的
`changeSemitones`。不满足条件返回 null，不能把 null 解释为平调或无语音。

这是一条音轨的周期性证据，音乐、多声源、声调及八度误检均可能影响结果；周期性
和有效帧比例不是语音概率。中文词内升降不能直接当作疑问或重音，因此音高不自动
改写 `candidateWords`。Agent 应结合语义、词间间隔和响度检查短句边界，再明确写入
`semanticUnits`，不能根据局部音高变化拆开语义完整的词组或机械增加音效。

真实口播 03 的 54 个单元中仅 15 个有足够音高帧，TTS 为 28/36；低覆盖率返回明确
提示，尚不足以宣称完整语气识别。静音输入不生成测量；原转写、人工强调和既有
响度候选均保持原样。已知频率、升降扫频、静音、低电平、直流、宽带噪声、范围外
频率、缺少边缘帧及非有限输入已用原生测试验证。新方法使旧缓存失效，重复请求和
版本冲突仍遵守原协议。音高证据与桌面/手机界面报告在 `analysis/pitch-report.json`
及 `pitch-{desktop,mobile}.png`，测试信号不能代替真实口播音高标注的准确率评测。

声学间隔测量使用完整 20 ms PCM 窗口，RMS ≤ -45 dBFS 且采样峰值 ≤ -35 dBFS，
连续至少 120 ms 才记入 `quietIntervals`。瞬态打断连续区间，不跨声音合并；末尾不足
一个窗口的样本不补零。`pauseSettings` 保存阈值。`quietGapSeconds[i]` 是第 i 个词结束到
第 i+1 个词开始之间，与测得低能量区间相交的最长连续时长，不是多段低能量时长之和。

Agent 可将当前分析的 `quietGapSeconds` 与同一份 `candidateWords` 一起传入
`plan_template`。长度必须是词数减一，每个值须有限、非负且不超过对应词间间隔。
提供后，仅将基于 ASR 间隔的停顿阈值判断替换为实测连续低能量时长判断；标点、说话人、
时长及字数预算仍生效，显式 `captionSpans` 可指定字幕边界，语义由 `semanticUnits` 单独维护。
旧 `phraseSpecs` 仅在迁移入口转换。工作台修改词级 JSON、应用普通转写或更换输入时清除旧证据。
低能量不是无语音的证明，背景音乐会掩盖口播停顿；零值只表示没有符合阈值的连续安静
区间，不能作为语义不断句的依据。词内的低能量区间不自动拆词或调整 ASR 边界。

真实验证：本地 TTS 检出 7 段区间，映射后 7 个词间间隔得到 0.16–0.26 秒连续低能量
证据；参考 03 在混合音轨上没有符合阈值的区间；静音样本为 0–3.64 秒连续区间且不
生成词。采用证据的默认编排分别得到 3 句和 4 句，原 ASR 间隔编排为 4 句和 5 句，
所有词及时间保留；句数改变不是剪辑质量改善的证明。重复请求、转写保持、UI 传参和
手动编辑清除证据均通过验证。桌面和手机检查无页面错误或横向溢出；报告及截图在
`analysis/pause-report.json` 和 `pause-{desktop,mobile}.png`。

### 按句子检索声音

工作台“音效库”的“匹配声音”和 MCP `search_template_sounds` 支持本地多语语义检索。
输入 `query`（句子、意图或声音需求）、`kind`（`sound_effect` / `background_music`）、
`maxDurationSeconds`（0.02–600 秒）和 `limit`（1–20），可选 `includeReview` 默认 false。
默认只检索用途匹配的已确认声音；显式开启后也返回用途尚未确认的声部和瞬态候选，
已排除声音始终不返回。时长上限用于筛选原声音，不隐式截断或循环声音。

复用本地 multilingual-e5-small，方法为 `sound-metadata-e5-v1`，以名称、说明和标签
计算余弦相似度。输出完整声音记录、revision、音频哈希、`canBind`、截断提示及匹配
当前音频哈希的人声/音乐评估；返回前复核条目版本和文件哈希。待试听结果的 `canBind`
始终为 false；检索不会确认素材或修改模板。工作台可编辑说明和标签，经原有 CAS
审阅接口保存，以积累经过试听的音色、用途和情绪描述。

默认 `matchBy: "metadata"` 不直接对声音波形进行语义匹配。现有候选多数只有通用分离说明，较高文本相似度
不能证明实际音色符合查询，也不是质量或可用性分数。需要补充真实试听和描述，或后续
使用下述音频内容检索辅助，才能评估选音质量。说明模式仅使用本地文本模型。

本机验证：78 条声音（76 待试听、2 已排除）时，默认查询返回空结果；开启待试听、
最长 1 秒时筛出 45 条候选，实测约 3.95 秒完成排序，返回结果均不可直接绑定。
已验证音频文件读取、检测哈希匹配、非法时长拒绝、库记录不变、真实 MCP 调用，及
桌面/手机的空结果、候选列表、音频元数据加载和说明/标签编辑入口。
报告在 `analysis/sound-search-report.json`，这不等于完成音效试听或选音质量验收。

工作台另有“声音内容”模式，对应 MCP 的 `matchBy: "audio"`。
使用本地 `laion/clap-htsat-unfused`，固定 revision
`8fa0f1c6d0433df6e97c127f64b2a1d6c0dcda8a`，方法 `sound-audio-clap-v1`；
权重 SHA-256 为 `1cd3c601bc4afe0fa87be3de4c13dd2cfadd249fac1e29acf74a9b296c3219bb`。
模型基于英文描述，此模式要求英文及英文标点；Agent 应先把中文句子意图转换成英文
音色需求，例如 `A short click sound effect.`，不能直接把中文送入模型并声称支持中文音频匹配。

源声音转为 48 kHz 单声道，按 10 秒窗口、5 秒步长覆盖全长，每个窗口产生 512 维
音频向量，与描述向量计算余弦相似度。输入窗口从不超过 10 秒，避免模型随机裁切长音频。
短声音采用模型的 `repeatpad` 重复补齐方式，并明确返回 `short_audio_repeated_for_model`；
这会影响瞬态和节奏感知，不等于原音频实际重复播放。描述最多 77 token，截断会报告。

排序使用最高窗口相似度，`audioMatch.bestWindow` 给出声音文件内的相对起止秒数，
同时返回 `meanWindowScore`、窗口数量和预处理参数；多窗口返回局部匹配提示。
工作台可定位该区间以核听。相似度不证明干净、好听或适合实际剪辑，现有 AST 残留
人声/音乐证据仍单独显示，未试听条目仍不可绑定。源文件推理前后均核验 SHA-256，
Rust 复核模型身份、向量、窗口覆盖、源记录及版本；不上传音频。
单次音频检索最多 128 条、累计 30 分钟，需用时长筛选缩小更大候选集。

真实验证：人声和贝斯声部对各自英文描述的相似度约为 0.582 和 0.589，明显高于
该小样本中的交叉描述。对 45 条候选音频（各条不超过 1 秒）查询点击声
约 6.22 秒完成；首位为 `reference-46-drums-candidate-01`，CLAP 分数 0.503，
其 AST 人声/音乐分数分别约 0.042/0.011，均只是未校准的模型证据。
两次检索返回相同结果，中文请求被拒绝，默认已确认范围仍返回空，库状态未改变；
桌面、手机、匹配定位和真实 MCP 调用已验证。报告为 `analysis/audio-search-report.json`，
原始三类探针为 `clap-probe-{input,output}.json`。这不是完整音色标注评测或试听确认。

`614241f622f53c4eeff9890bdc4f31cfecc418b3`。Rust 按完整对齐词拆分长口播，所有分段

### 模板与声音

1. `list_templates`：读取模板、参考审计、声音目录与分离任务。
2. `template_schema`：读取权威结构；`read_template` 读取目标版本。
3. `save_template`：传完整模板、`baseRevision`、`idempotencyKey`。
   新建版本基数为 0；冲突后重新读取并合并；同一请求重试使用同一 key。
4. `separate_template_audio`：以有声参考 ID 排队，状态通过目录读取。
5. `review_template_sound`：试听之后分类确认，保留来源和污染情况。
6. `plan_template`：传实测词时间与模板，获得可检查的短句、元素实例、布局和警告。

模板保存采用 SQLite 事务，历史版本和请求回执持久保存。`plan_template` 是试编排，
不会直接修改当前工程。接入共享工程时仍须遵守 `agent-smart-edit.md` 的 revision、
幂等与回读协议。

## 可编辑时间线编译

`apply_template` 接收 `projectId`、`sceneId`、`baseRevision`、`idempotencyKey`、
`startTimeSeconds` 和原始 `PlanInput`。它读取现有工程，通过 Rust 的
`POST /templates/compile` 编译，再经唯一的 `/api/projects/{id}` CAS 写入接口提交。
工程画布必须与模板一致。默认保留主视频；显式提供 `source: {trackId, elementId}`
时，只重编排指定的主轨视频。MCP 从真实素材索引读取源尺寸和时长传给 Rust。

已实现文字角色、矩形底板、背景、边框、下划线和椭圆圈注。文字保留内容、字体、
字形、描边、阴影、底色与区域内缩小排版。编辑器的字号使用 90 像素高基准，编译器
转换模板的设计像素，避免直接写入导致字号放大。字重目前映射为常规/粗体，其他
字重有显式警告。动效包括位置、缩放、旋转、不透明度和可编辑 Bezier 控制柄。
同一元素角色按时间分轨，层次按 z 排序；重叠实例分到独立轨道。

### 图标、贴纸与补充画面

`apply_template` 和工作台的“应用到工程”支持 `visualBindings`，将模板资源槽绑定到
所选工程的媒体目录。`icon`、`sticker` 使用图片，`broll` 使用图片或视频。先通过
编辑器或 `import_media` 导入素材，再指定资源槽 ID 和工程媒体 ID：

```json
{"visualBindings":[
  {"resourceId":"badge","mediaId":"project-image-id","fit":"contain"},
  {"resourceId":"cutaway","mediaId":"project-video-id","sourceStartSeconds":2,"fit":"cover"}
]}
```

绑定只影响本次应用，不改写保存的模板或参考证据。没有覆盖绑定时，可使用资源自身的
`assetId`，但这个 ID 必须存在于当前工程目录。尚未绑定的槽继续提示并跳过。语义意图、
互斥组、强调数量、保护区域和时序规则仍由原编排器执行。

图片保留透明通道；输出使用现有 `image`/`video` 时间线元素，包含位置、等比缩放、
阴影及可编辑关键帧。`contain` 完整显示，`cover` 用可编辑矩形遮罩裁切到资源区域。
视频从指定素材起点播放，每个实例独立使用这一范围；长度不足直接拒绝整次编译，
不自动循环、变速或冻结末帧。补充视频的源声音关闭，避免重复叠加口播。

未知/重复资源槽、错误媒体类型、缺失尺寸和越界起点会拒绝编译。应用哈希包含绑定、
尺寸、时长及目录中的媒体 ID、大小、修改时间等身份元数据；这不是对项目素材字节的
独立 SHA 校验。真实 MCP 和 UI 均从当前工程读取媒体目录，UI 写入前会再次读取。
推荐结果读取时重新计算当前编译器支持的元素，避免缓存继续把已支持的图标标为不支持。

验收工程 `f3c28729-b2c5-4d08-9f4d-86b86d626467` revision 2 含 12 个可编辑实例：
两张由 Lucide 图标栅格化的透明 PNG、一段裁切视频以及文字。重复应用回读通过，
结构检查无错误；入场、稳定展示和末段代表帧已检查。12.5 秒 H.264 审阅导出完成，
完整解码通过，导出第 6 秒确认补充视频按时间播放。原参考仍含烧录文字，且本次
补充画面按设计静音，所以该工程只验证视觉资源链路，不作为最终成片交付。
工作台桌面/手机资源选择、绑定请求、12 实例预检、修改绑定后预检失效均已实测。

当前是工程素材绑定，尚未实现跨工程视觉资源包、动态贴纸帧时序或自动挑选补充画面。
设计页仍以文字和基础图形预览为主，资源的权威画面来自实际编辑器和导出。

编译结果在元素参数中保留应用标记和请求哈希；同一请求重放不会重复叠加。
部分实例被删除时拒绝重放并要求检查工程。标记随元素存在，全部删除后的重新应用
不会被视为重放，这与模板库的持久保存回执不同。提交后再读取工程并由 Rust
核验实例标记，返回 `verified` 和 `readbackRevision`。文件版本与编辑器内部版本
是两个计数，渲染前应检查 `loadedFileRevision`。

实际验收工程 `0d7c0420-0f01-4dca-bd5a-34e306eda754` 的文件 revision 3
包含参考 03 原视频和 18 个可编辑实例；8 个语义短句、4 条文字轨道、8 个动效关键帧。
结构检查无错误，代表帧已复核，1080×1920、12 fps、H.264/AAC 的审阅 MP4

仅证明编译与导出链路，不能作为合格成片。

主画面编译支持铺满、12% 近景推近、圆形嵌入、单源画中画区域和模糊填充。
在语义短句的布局变化点分段，停顿沿用前一个布局，覆盖源片段的完整时间。
裁切起点按真实时间递增。布局编译将已启用的主视频原声保留为一条连续的 upload 音轨，
保留起点、时长、素材裁切、音量、处理参数及原轨的静音/独奏状态；所有布局视频明确
关闭源声音，避免视觉分段进入音频混音路径或双重播放。原本关闭源声音的片段或已知

输出后均为可编辑参数。切换支持硬切、滑入、缩放入场、擦入和模糊入场；
溶解仍明确返回警告。擦入通过与原裁切相交的 split 蒙版线性展开，保留焦点裁切及圆形蒙版；
模糊入场通过可编辑的 blur 强度关键帧从 85 降至 0。入场时长不超过新片段一半，
主画面及第二路均保留原有源时间，连续原声不变。这些是新布局的入场效果，
不是前后两组布局的重叠转场；擦入起始会露出底层画布，不能当成无黑场的跨布局擦除。
分屏和双源画中画通过 `layout.secondary` 定义第二路资源及区域：

```json
{"mode":"split","videoRegion":{"x":0,"y":0,"width":1,"height":0.5},
 "secondary":{"resourceId":"secondary-footage","region":{"x":0,"y":0.5,"width":1,"height":0.5}}}
```

该资源必须是模板中的 `broll` 槽，再用 `visualBindings` 绑定工程图片或视频。
分屏的两个区域不能相交，第二路必填；画中画允许区域重叠，第二路在主画面上方。
未设置第二路的旧画中画模板保留单源嵌入行为。`secondary` 只适用于这两种布局，
旧 JSON 未提供此字段时不会在序列化中补出字段，保留原应用请求的兼容性。

第二路随对应语义布局出现。视频时间从该资源在本次编排中第一次出现起连续递增，

### 试映应用的原视频区域

动态样式 `Application` 可提供 `videoRegion: {x,y,width,height}`，所有值使用输出画布比例。省略时原视频保持完整画布；提供时 Rust 在样式投影之后仅修改应用布局的 `videoRegion`，并验证区域边界。不会改变文字图层、字号、动画或声音事件。此字段可通过 `prepare_dynamic_asset_application` 调用。

试映页“原视频区域”控件和链接 `videoX/videoY/videoWidth/videoHeight` 对应同一契约。开启默认将原视频放在上方 80% 区域；字幕仍需按实际样式独立定位。原视频裁切填满区域，可用输入的 `focalPoint` 修正人物构图；这不是自动主体避让。保存样式组合不收录原视频构图，应用评审则保留具体区域并在试用链接中复现。
