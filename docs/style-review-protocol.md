# 独立样式的版本与应用评审

独立样式的评审对象是已保存版本的一次明确应用。分数不能自动继承到其他画幅、摆放、组合或修改后的版本；技术导出成功不自动生成审美分数。

## 调用顺序

1. 保存样式；多样式组合先使用 `capture_dynamic_asset` 捕获再保存。保留 assetId/revision。
2. 调用 `prepare_dynamic_asset_application`，保留完整 Application 请求（画布、摆放、输入、独立大小和字幕宽度）。
3. 使用返回模板提交生产，可改变生产模板 ID；不改其视觉、内容绑定、时间、资源或编排字段。如需改动，先写回或另存样式再重新应用。
4. 等待同一生产项全部成片导出，至少三个样例。实际检查画面、连续动效、长短文字适配和编辑性；是否试听单独填写。
5. 用 `review_dynamic_asset` 提交 `{application, review}`。`review` 沿用整片评审的五项依据、reviewer、inspection、limitations、blockingFindings、listened，以及 batchId/item/templateId/templateRevision 和所有成片 fixture/sha256。
6. 用 `list_dynamic_asset_reviews` 回读；`current` 为 false 的记录只能用于历史追溯。`evidenceCurrent` 独立检查生产模板哈希及登记的全部成片证据是否仍与记录一致，不重新解码文件。样式升级不会使尚未变化的历史视频失去查看入口；生产图或成片证据变化则隐藏该记录的播放入口。

原生 schema：GET `/templates/dynamic-assets/schema` 的 qualityReview 和 qualityReviewCapabilities。
HTTP：GET/POST `/templates/dynamic-assets/reviews`。Web 通过现有 `/api/footage` 代理访问同一端点。

## 校验与边界

Rust 使用当前保存的样式和 Application 重新投影，和生产项原始模板逐字段比较，仅允许模板 ID/revision 不同；数值比较允许 4 倍机器精度乘以 max(1,绝对值) 的 JSON 往返末位误差，字符串、整数、字段集合和数组顺序仍严格匹配。生产阶段分配的新模板 revision 从生产项读取，再沿用已有评审的版本、发布状态、哈希、完整样例覆盖和技术检查校验。保存 definitionHash/applicationHash 和内容寻址记录 ID；完全相同的提交幂等。

读取时重新校验来源与生产证据，源样式变更、生产图结构或成片哈希变化会使记录不再 current。修改过程中，UI 明确记录只针对保存版。此机制不是独立观片裁判：检查范围、评分依据和试听状态仍由评审人如实填写。

组合关系没有被忽略或模糊匹配：任意额外字幕、图标或临时图层修改都会使单一样式的应用对比失败。组合本身保存为样式后，可按同一协议评审。旧整片模板分数不自动迁移。当前版本没有记录时显示“待评审”，不会拿历史最高分作为默认值。

内部阈值仍为总分至少 90 且没有阻断项，分项上限为构图 25、动效 25、素材 20、适配 20、编辑性 10。UI 明确称为“该应用内部评分”，不承诺任意组合、开拍同等质感或用户审美认可。至少三个样例也不自动证明场景多样性。

## 已验证范围

原生测试覆盖可重复保存、100 分但有阻断项不能达标、不相关图结构、被替换的成片、旧样式版本失效，以及普通生产分配新模板版本的情况。共享评审测试覆盖不完整/重复证据与分项限制。MCP 测试覆盖新工具的参数转发和原生错误保留。

真实服务检查使用现有青色弹字组合批次：单一样式 Application 试图引用额外字幕的实际成片被拒绝，评审库无变化。浏览器检查待评审展示和未保存提醒，样式库无变化。纸签 revision 2 已关联三份实际导出，阶段性抽帧评审 82/100（需完善、未试听），并通过页面刷新回读。多人复评、更多场景的最终视觉/听感评审尚未完成；此文档不是样式质量验收通过声明。

工作台将历史评审放在独立折叠区，标注原版本及不适用于当前版本。成片播放器只在用户展开后创建，折叠时卸载；不自动播放。当前版本标题和记录计数不包含历史分数。

播放器在收起成片、历史区、整个验收区或切换样式版本时停止并释放资源；同一评审区一次只播放一段。该交互已用静音真实播放验证，不因此将评审 listened 字段改为 true。

## 原生透明度稳定段提示

计划与编译警告可返回 `text_opacity_hold_short:<instanceId>:<start>:<end>:<held>:<recommended>`，数值均为秒。在声音事件和生命周期已确定、motionTiming已解析后，Rust对有变化的文字opacity轨道计算最长连续全不透明常值段（包括首尾钳位）；当小于 `min(0.15秒, 实例时长×0.5)` 时提示。无opacity轨道、恒定透明度、非文字及空内容不触发。它是有意保守的创作提示，不阻止执行、不改变时间或样式，也不是可读性评分。插值变化段不计入全不透明稳定段；其他图层、父组透明度、遮挡、滤镜和缩放不在此项检查范围内，必须结合实际画面判断。

Web仅翻译原生结果，展示时间范围、稳定段与建议时长、缩短淡入退场等修改建议；相同文案的多层提示合并。AI可从实例ID关联计划元素。没有提示不构成审美或可读性通过证明。

样式库卡片和详情共用原生评审响应。卡片只显示匹配保存版本且current/evidenceCurrent有效的应用记录；单份显示该应用分数及原生达标标记，多份显示记录数与达标应用数，不取最高分代表整个样式。读取失败与待评审明确区分。版本变化或刷新库会重新读取。详情的试用链接保留显式intents数组（包括代表所有语义的空数组），避免复用已评审布局时丢失触发规则。

字幕预算诊断区分整句与不可拆分的转写词。`caption_exceeds_character_budget`
和 `caption_exceeds_phrase_duration` 表示多词显示单元的总长度或总时长超限；
`aligned_word_exceeds_character_budget` 和 `aligned_word_exceeds_phrase_duration`
仅在至少一个转写词自身超限时产生。两种问题可同时存在。阅读速度仍按既有
规则独立判断；诊断不自动改写手工范围、拆开转写词或延长显示时间。历史生产
回执中的旧诊断保持原记录，新的计划调用返回细分后的诊断。

## 预览诊断定位

独立预览、应用示例预览和真实样例预览返回原生编译计划的 `captions`，含 `id`、`text`、`start`、`end` 和逐句 `warnings`。这是同一计划的只读投影，Web 不重新分词、生成时间或计算诊断阈值。示例预览仍以 `example.timingSource=synthetic_example` 标明合成时间；真实预览保留 `timingSource` 来源标识。AI也可直接使用这些字段定位需要检查的句子。

预览检查下的“定位需检查的字幕”展示逐句原文和区间。点击暂停播放，将画面和原声音频定位到该句开始，并将画布滚入视野；不改变样式、标注、实际时长或诊断阈值。列表使用字幕显示单元时间，因此独立花字自身可能在句内较晚出现。此入口帮助复查，不代表已完成试听或可读性验收。

## 候选评分与阅读预算

`evaluate_template_plans` / `/templates/evaluate` 的阅读指标使用声音输入的
`captionPolicy.maxCharactersPerSecond`；未覆盖时使用模板 `segmentation` 的对应值。
它与字幕的 `reading_speed_exceeds_limit` 诊断共用 Unicode 字符计数及 0.05 秒最小时长分母。
该分母用于数值稳定，与真实可读性验收不同。指标仍是每句超预算负担的均值转换，
不是对画面字号、人物遮挡、背景干扰或语义分句质量的测量。

评分返回 `scoreModel: heuristic-v2` 和 `metricVersion: caption-budget-v2`。
旧版固定按每秒 8 字评分，不能与新版直接比较来宣称画质提升。历史评审和成片不变；
候选数值改变不自动修改独立样式的五项人工评审分数。没有视觉指标时，左右摆放
可能得到相同分数，AI 必须检查实际画面，不可把第一名称为最佳构图。

偏好回执和训练版本保留 `metricVersion`。未标版本或版本不同的历史反馈保留可追溯，
不参与当前版本训练；旧训练档读取时 `active=false` 并返回 `calibrationWarning`，
数据库中的旧档不会因读取被覆盖。积累当前版本足量有效对照后再训练启用。

## 跨输入应用评审

同一风格在不同画面上可以使用不同的 Application。人物、讲解图示和行宽各不相同时，使用独立的 `qualityReviewSeries` 契约登记一组应用；不再为了符合单应用评审而强迫所有输入共用坐标。

入口为 GET/POST `/templates/dynamic-assets/review-series`，MCP 对应 `list_dynamic_asset_review_series` / `review_dynamic_asset_series`。提交对象为 `{cases: [{application, review, rationale}], rationale, coverage, limitations}`。`review` 使用现有五项评分及生产证据结构，逐项记录检查范围、未解决问题和试听状态；每个 case 的 `rationale` 说明输入特点与本次调整原因。系列的 `coverage` 必须说明真正检查过的语言、词长、背景和画幅。

Rust 要求同一当前样式版本，每个 Application 精确重建到对应生产图。每个 case 至少一份成片并覆盖该生产项全部预览，系列合计至少三个不同成片哈希；重复生产项、重复证据、错误哈希、未发布或技术检查失败均拒绝。不同哈希不自动证明输入语义或背景不同，覆盖范围仍需评审人依据源视频如实说明。

系列分数取最差 case，内部达标、试听和最终审美标记均要求全部 case 满足条件。一个低分/阻断 case 不会被其他高分平均掉，未试听的 case 不会被升级为最终验收。结果以独立记录保存，幂等重试不重复创建；不覆盖单应用分数、样式定义或项目。原单应用接口仍要求同一 Application 的至少三份成片。

回读重新校验整个系列和各 case 的 `current/evidenceCurrent`。版本升级后记录进入历史；成片证据变化时对应 case 不再展示当前视频。工作台展示最低分、各应用调整原因、覆盖和限制，并逐 case 复用成片入口；只在展开后创建播放器，折叠后释放。试用评审布局时保留其 `minDisplaySeconds` 显式覆盖，避免重试时改变阅读时长规则。
