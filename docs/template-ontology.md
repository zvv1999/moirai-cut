# 剪辑本体 v2

当前保存、编排和编译共同使用 `moirai.template.v2`，计划为 `moirai.template-plan.v2`。
工作台直接编辑该模型；`ontology` 接口是同一模型的兼容别名，不再维护读取投影。
业务定义、约束和迁移都在 Rust，Web/MCP 负责编辑和传输。

效果工作台保存 `moirai.dynamic-asset.v1` 图层与样式定义，Rust 将其投影到共享的模板编译模型。示例文字和模拟词时间仅用于预览；应用后的实际字幕与词时间不保存回效果定义。

## 结构所有权（2026-10-09 核对）

“可复用模板”在效果库中具体指 `dynamic_asset::Definition`。历史命名 `model::Template`
是更宽的**可编译编排文档**，既能承载规则，也能承载应用投影及场景编排；不能因为它叫
Template 或成功保存，就断言它不含本次输入信息。两个 schema 接口的 `modelBoundaries`
返回同一份 Rust 职责说明，供工作台与 AI 使用。

| 对象 | 所有权 | 不由它决定 |
| --- | --- | --- |
| `Definition` | 图层、外观、资源槽及默认绑定、图文关系、相对运动、内容绑定和使用指南 | 某次输入的词下标、实际事件时刻、人物保护区 |
| `Application` | 样式 ID/版本、本次文字、画幅、位置、尺度、源视频构图及展示覆盖参数 | 修改模板库原定义 |
| `Sample` | 媒体及转录版本、语义/字幕/短语、声音/时间事件、内容级素材替代 | 可复用样式的配色和设计身份 |
| `Template` | 可执行的元素/效果/关系与场景编排；可含 `rigidTransforms`、具体生命周期事件 ID | 自动证明这份编排可通用于其他输入 |
| `EditPlan` | 已解析内容、起止时刻、布局及转场实例 | 回写 TTS 词时间或样式定义 |
| 策略与测量证据 | 策略声明约束；证据绑定被观察的内容和应用上下文 | 由字段齐全、测量数值或几何通过推导审美验收 |

样式设计坐标、演示文案、入退场秒数是合理的设计参数。它们是否属于具体输入，取决于
语义和引用关系，而不是字段里是否出现坐标、文字或秒数。时间线的实际实例起止仍由
声音/TTS、语义、镜头等事件与编排规则解析。

`capture` 是从编排显式提取可复用视觉图的入口：无法表达的场景调度、应用旋转、转场
等会被拒绝，不静默丢字段。当前 Definition 不能保存完整场景转场规则；转场关系在
Template 的 composition 中组合。这是当前可复用图的能力范围，不应宣称所有组合均已支持。

抽象验证以“不串上下文、不丢关系、不改原定义、不把缺证据标成通过”为底线。
详见 [数据结构审计](template-data-model-audit-20261009.md)。

## 固定入退场与动态停留

视觉元素可选 `motionTiming: {enterEnd, exitStart, enterSeconds, exitSeconds}`。前两个字段是作者关键帧的归一化阶段边界，满足 `0 <= enterEnd < exitStart <= 1`；后两个字段是目标入场、退场秒数（0–30 秒）。没有此字段时，保留原先所有关键帧随实例时长缩放的行为。

调度首先确定字幕/关键词/生命周期的最终起止，再把元素自身 `motions` 的关键帧分别映射到入场、剩余停留、退场三个区间。若实例短于入退场时长之和，按比例压缩两阶段，中间停留归零，合并重合边界；不改变词时间或字幕边界。零时长入场直接使用入场完成值，零时长退场在片段结束消失，不产生贯穿整个停留期的意外淡出。

这个时钟只控制该元素自身的动作关键帧，不重映射语音对齐高亮、关系生成的状态关键帧或独立处理效果的时钟。数值与缓动仍由各轨道定义；切换时间模式本身不会生成缺少的入退场关键帧。`apply_template_element_envelope` / 效果的 `envelope` 草稿操作会生成 0/20%/80%/100% 的透明度关键帧及选定的入场动作，再写入 `motionTiming`。原有 `entrance` 操作仍生成归一化关键帧，若已有阶段时钟，则由该时钟解释进度。

编译输出仍是普通可编辑的实际时间关键帧，时间轴与渲染器无需持有第二套动效引擎。

## 正交组合

元素是独立特性的组合，不是“强调文字”“强调图片”“强调音效”等组合枚举。
增加一个角色不需要增加每种表现类型的对应分支。

| 特性 | 含义 | 消费者 |
| --- | --- | --- |
| `features.role` | 标题、强调、标注、背景等语义角色；允许未知 | 语义标记与检索；不选择渲染器 |
| `features.representation` | 文字、图片、视频、声音、几何形状 | 渲染编译与资源媒体兼容检查 |
| `features.mediaUse` | 图标、贴纸、补充画面、音效、音乐等用途 | 媒体使用策略；音频用途决定循环与包络 |
| `features.outline` | 只显示轮廓 | 支持的文字、几何图形渲染 |
| `features.accent` | 是否计入视觉强调预算 | 视觉编排；声音不占视觉强调名额 |
| `features.placement` | 元素固定区域或当前布局字幕区域 | 空间定位，不从“字幕”角色隐式推导 |
| `features.avoidProtectedRegions` | 是否避让保护区域 | 空间碰撞约束 |
| `binding` | 文案标题、字幕内容、关键词、人物、固定文案 | 内容绑定 |
| `styleId` / `motions` | 外观与随时间变化的通道 | 与角色独立的视觉处理 |
| `timing` / `intents` / `exclusiveGroup` | 时间锚点、匹配条件、互斥约束 | 时序编排 |

例如，同一个 `emphasis` 角色可以同时出现在文字、图片和声音实例上。
角色改成 `annotation` 不改变图片的媒体引用、文字的字体或声音的循环规则。
这不意味着物理上无意义的特性也能任意组合：声音使用音量包络，不接受视觉关键帧；
图片不能作为音频资产；文字必须有样式。不支持的能力不能通过改名获得。

## 资源需求、资产与绑定

`ResourceSlot` 只有身份、媒体需求、说明和标签，不含资产 ID，也不含资产审核状态。
`ResourceBinding` 单独表达 `{slotId, assetId, enabled}`。资产仍保存在原声音目录或工程媒体目录中，
不在每个模板里复制一份文件或资产事实。

模板文档的 `resourceBindings` 是保存的默认选择；一次 `PlanInput.resourceBindings`
可以覆盖它，包括用 `enabled:false` 解除本次使用。覆盖只作用于编排，不改模板定义。
`CompileInput.visualBindings` 继续提供工程媒体、裁切、源时间和焦点参数。

绑定不会批准音效。Rust 在保存和编译时按实际用途核对声音审核状态、目录记录和文件哈希；
视觉编译检查工程媒体的真实类型、尺寸、时长及使用区间。
一个资产可用于多个资源槽；一个使用上下文里，一个槽最多一个绑定。

## 空间、入场与转场

- `Layout` 只有空间区域、模式、适用意图和观察依据，没有 `transition` 字段。
- `LayoutEntrance` 是独立关系：指定目标布局、入场效果与时长，作用于进入的对象。
- `TransitionRule` 指定前后布局定义、效果和时长；不能省略前布局。
- 编排合并连续相同布局，生成有身份的 `LayoutInstance`。
- `TransitionInstance` 明确引用 `fromInstanceId` / `toInstanceId`，带实际发生区间。

直接切换和单层布局的交叉溶解由当前编译器执行。擦入、模糊、滑入、缩放仍作为入场效果工作。
交叉溶解在剪辑点前建立重叠：后画面渐入到前画面上，剪辑点、结束时间和连续源音频不变。
视频后画面必须有足够的源前置余量；否则明确失败。多层画面可显式组成 `composite` 组，
再指定组间转场；布局层的快捷转场仍限制每侧一个视觉层。

## 对齐内容、语义与字幕

`EditPlan.words` 是一份保留实际时间的词表；其他内容对象通过半开词范围
`[startWord, endWord)` 引用它，不复制带意图的词表到每个字幕对象中。

`SemanticUnit` 描述一个语义单元的词范围、表达意图、关键词范围与理由。
`CaptionCue` 描述一次显示的文本、词范围、起止时间，以及对应 `semanticIndex`。
一个语义单元可以对应多个字幕单元。语义索引只在当前计划内有效。

```json
{
  "semanticUnits": [{
    "startWord": 0, "endWord": 4,
    "intent": "emphasis",
    "keyword": {"startWord": 2, "endWord": 4},
    "rationale": "一个完整观点"
  }],
  "captionSpans": [
    {"startWord": 0, "endWord": 2},
    {"startWord": 2, "endWord": 4}
  ]
}
```

语义单元必须有序完整覆盖词表，关键词必须位于所属单元内。
显式字幕范围也必须完整覆盖词表，不能跨越语义边界；留空时在每个语义单元内部根据
字数、阅读速度、实测停顿等生成字幕。修改字幕预算不会重写意图、关键词或音频时间。
没有显式语义时，以句末和说话人边界产生可审阅的启发式语义单元，而不是用字幕长度推导段落。

时间锚点是 `cue_start`、`cue_end`、`semantic_start`、`semantic_end`、`keyword_start`、`video_start`。
语义锚点只触发一次，字幕拆成多屏不会把段落入场重复多次。

## 独立策略

| 策略 | 字段示例 | 负责 |
| --- | --- | --- |
| `segmentation` | maxCharacters、maxPhraseSeconds、pauseBoundarySeconds | 字幕分段与阅读预算 |
| `visualRhythm` | minDisplaySeconds、maxAccentsPerCue | 视觉展示与强调密度 |
| `audioPlacement` | effectCooldownSeconds | 声音的时间间隔 |
| `mix` | musicGainDb、musicDuckDb、effectGainDb | 音量与口播压低包络 |

`maxPhraseSeconds` 保留原字段名，但只属于字幕策略，不再控制语义段落边界。
计划的 `elements` 仅包含视觉实例，`sounds` 仅包含声音实例，二者都保留元素定义身份。
声音实例保留语义角色和媒体用途；不会再次作为视觉元素编译。

## 对象关系

参考视频提供观察依据；资产提供实际媒体；TTS 是生成过程，转写是分析结果。
模板定义可复用规则，计划实例化一次输入，工程保存可人工继续编辑的时间线，导出生成成片资产。
证据、模型判断、资产审核、编译器能力是独立事实，检索分数不能变成审核通过。
“网感”是节奏、信息密度、情绪及视听同步的组合评价，不是资产类型。

## 迁移与兼容

`legacy_model.rs` / `legacy.rs` / `legacy_seed.rs` 仅处理旧格式与旧研究集。
运行时规划器、资源解析器、混音器和编译器不再使用 `ElementKind`、`RhythmRules` 或旧 `Phrase`。
原来的本体读取层已移除，只留下同模型接口别名。

- 启动时将当前 v1 模板事务性迁移到 v2，原 JSON 留在 `template_schema_source`，修订号不变。
- 后续保存、读取、导出都使用 v2。历史模板版本保留，读取时在边界转换。
- 未验证但已选择的旧资产保留为停用绑定，不丢失引用，也不自动批准。
- 旧 `Layout.transition` 转为独立入场关系，不虚构前后画面转场。
- 旧 `phraseSpecs` 在请求边界同时转为语义单元和显式字幕范围，保留旧请求的字幕边界。
- 旧保存回执和旧编译请求的哈希有兼容校验；读取结果归一到 v2，同一旧请求不会重复写入。
- 新旧内容字段同时出现会被拒绝，防止两套定义互相覆盖。

工作台“设计”和“本体”都直接编辑新特性；“布局”分别编辑入场和前后布局关系；
“断句与编排”分别编辑语义段落与字幕词范围。`/schema` 是权威结构定义。

## 正交能力：定义、应用、关系

“正交”指能力实现与元素种类独立，不是时间线性或算法复杂度。字幕是文字的一种用途；
画面可以是图片、视频或图形。滤镜、动效和转场不需要分别实现“字幕滤镜”“视频滤镜”。
相容性在应用关系上校验，声音不接受视觉滤镜。

`composition` 是以下独立集合的命名空间，默认空值保持旧 v2 请求的序列化和幂等身份：

| 集合 | 关系及执行 |
| --- | --- |
| `treatments` | 可复用的模糊、调色、动效定义 |
| `applications` | 处理定义 → 元素、元素组或布局画面；数组顺序就是叠加顺序 |
| `groups` | 元素选择集合；`composite:true` 将成员先合成，再施加组处理 |
| `arrangements` | 组成员在指定区域内按列数、间距排列 |
| `transitionEffects` | 可复用的转场算法与时长，目前执行 `dissolve` |
| `transitions` | 前元素定义、后元素定义 → 转场定义；规划时解析为相邻实例关系 |
| `spatialRelations` | 子元素 → 参照元素，支持居中、上下左右、间距和偏移 |
| `scheduling` | 元素 → 统一时间事件条件、评分变量和时序约束 |
| `layoutPolicy` | 布局基础分、意图权重、重复惩罚、最短保持及时间来源 |
| `resourceRequirements` | 资源槽 → 媒体尺寸、时长、画幅、裁切、标签和备用槽约束 |

透明度、缩放动效按倍率相乘；位移以像素相加，旋转以角度相加。组合编译会在模板帧率
上求值原贝塞尔曲线，保留关键节点，写出可编辑关键帧。转场透明度再乘到已有透明度上，
不替换其他动效通道；滤镜追加到有序效果栈。预览和导出消费同一时间线数据。
`TransitionEffect.outgoingFade` 控制前元素是否同时淡出：透明字幕通常开启，
全幅画面覆盖通常关闭。它是转场参数，不由字幕或视频类型暗中选择。
当前实现使用普通 alpha 合成的交叠包络，不等同于隔离合成表面内的线性像素混合。

例如，`soft` 可以应用到字幕和产品图片，同一个 `cross` 可以用于字幕接续和图片接续：

```json
{
  "treatments": [{"id":"soft","operation":{"kind":"blur","intensity":12}}],
  "applications": [
    {"treatmentId":"soft","target":{"kind":"element","id":"caption"},"enabled":true},
    {"treatmentId":"soft","target":{"kind":"element","id":"product"},"enabled":true}
  ],
  "transitionEffects": [{"id":"cross","effect":"dissolve","durationSeconds":0.2}],
  "transitions": [
    {"id":"caption-next","fromElementId":"caption","toElementId":"caption","effectId":"cross"},
    {"id":"product-next","fromElementId":"product","toElementId":"product","effectId":"cross"}
  ]
}
```

定义相同不代表实例相同：`caption → caption` 指连续字幕实例之间的关系。
规划输出 `elementTransitions` 保存实际两端实例和发生区间，编译器执行这些关系。
实例没有相邻前项时不会凭空产生转场；多个前项或多个转场争用同一后项会失败。

## 声音驱动的编排变量

声音是时间驱动输入，口播是带词、语义和韵律信息的一种声音。`PlanInput` 接受词表、
`events` 或两者；纯节拍编排不需要伪造字幕。事件类型为全片、语义、字幕、关键词、镜头、
语音、节拍、起音、停顿、能量峰和乐段，每个事件包含源 ID、时间、强度、置信度和证据说明。
旧 `soundEvents` 在输入边界转成相同事件。词表衍生的语义、字幕和关键词事件使用保留的
`auto-` ID。所有元素和布局使用同一事件调度器，`EditPlan.events` 保留归一后的输入。
这些是调用方提供的分析证据，本次没有新增自动节拍提取器，也不把事件标签当成实测证明。

声音编排规则使用 `minConfidence`、`minStrength`、`cooldownSeconds`、`maxOccurrences`，
并计算 `strengthWeight * strength + confidenceWeight * confidence - repetitionPenalty * count`。
同一事件的候选按分数和稳定 ID 排序；互斥组占用实际时间区间。
`scheduleDecisions` 记录分数、是否采用及阈值、冷却、次数、互斥、资源、时长等原因。
显式规则覆盖元素的默认时间锚点；不存在额外的字幕调度循环。

`scheduling[].endAtNextEvent: true` 将元素结束边界设为下一个同类事件的起点，
最后一个事件保持到输入结束，并继续受 `maxSeconds` 限制。它在意图、次数和强度筛选前
寻找下一个事件，因此被筛掉的事件仍可结束上一画面；同时发生的事件不互相截断。
起止边界都使用该元素的 `offsetSeconds`。这适用于跨语音停顿保持的画面、侧栏和章节卡，
可以让相邻实例连接转场；不改变字幕单元、对齐词或原始声音的时间。

自动字幕断句同时尊重句末、逗号/冒号分句、说话人变化和实测停顿，之后再受字数和时长
预算约束。数字分隔符不作为分句边界。显式 `captionSpans` 仍优先，长句缺少标点或词级
对齐过碎时仍需 Agent 提供语义断句；不会用修改词时间来掩盖阅读速度过快。

`layoutPolicy.eventKind` 可将布局切换绑定到节拍、起音或乐段等声音事件；不设置时沿用
口播语义时间。布局分数是基础分 + 意图匹配权重 - 历史使用次数 × 重复惩罚，
最短保持限制切换频率。声音事件中的语音区间也参与音乐压低，不要求先有 ASR 词表。
声音驱动的布局实例保留 `soundEventId`；没有字幕时 `captionIndex` 为 `null`，不制造字幕引用。

## 空间与资源约束

相对定位先检查环，再按依赖顺序计算。参照元素必须唯一覆盖子元素的完整时间区间；
结果必须位于画布内并满足保护区域约束。不会用缺失参照或越界的坐标悄悄继续。
`followMotion:true` 将父元素的位移、缩放、旋转变化与子元素自身动效组合，在模板帧率
采样成可编辑关键帧。父元素初始缩放不能为零。它不自动测量人体运动轨迹。
`arrangements` 支持等分网格；同一元素不能同时由网格和相对定位拥有区域。
`composite:true` 将子轨道保存在时间线 `renderGroup` 中，在透明离屏表面先合成成员，
再施加组滤镜、动效、透明度和组转场。组和元素 ID 必须不同，复合组不能共享成员，
不能跨越中间的外部图层。组可移动及裁切，子成员保留原素材引用和可编辑参数。

资源约束由编译器核对真实工程媒体目录。时长按源入点之后的余量计算，标签缺失不会当成
匹配通过。备用槽按声明顺序跳过目录条件不合格的绑定，并保留源入点与裁切方式；须满足目标槽的
约束。显式停用的绑定不会被备用槽重新启用。必需槽无法解析会报错，可选槽保留未解析提示。
当前这些附加约束用于视觉媒体，声音仍走原声音目录审核及用途校验。

## 能力边界与后续扩展

`template_schema.capabilities` 同时暴露实际支持的处理、目标、转场、空间关系和余量要求。
新增滤镜应增加独立定义与编译处理，而不是扩展每一种元素；新增转场应增加关系算子，
不向字幕、图片、视频各塞一套转场实现。

`POST /templates/preflight` 接收完整 `CompileInput`，复用 `/compile` 的声音解析与实际编译，
不写工程。返回 `executable`、结构化 `issues`、警告、元素数及完整请求指纹。
这是指定输入、工程修订和目录条件下的检查；工程或素材变化后需要重新检查，实际写入仍走 CAS。

`POST /templates/evaluate` 接收 `request`、可选 `alternatives` 模板、`resourceCandidates` 素材绑定、
`weights` 及 `maxCandidates`（默认 12，上限 24）。原方案、稳定/变化布局策略和素材组合均作为
完整候选实际编译，失败候选保留原因且不能胜出。结果含选中 ID、每个完整请求、计划、分项及排名。
有界搜索不是全局最优证明，达到上限会返回 `searchTruncated`。

当前评分模型 `heuristic-v1`：时间覆盖率、8 字/秒阅读负担、120 ms 事件对齐、800 ms 镜头保持、
整片布局重复率及素材标签匹配。覆盖率和事件对齐同时计入视觉及声音实例；只有一个布局时变化度
使用中性 0.5。各分项归一化后按显式权重加权到 0–100；缺少素材相关性证据时
使用中性 0.5。它是可解释的方案比较指标，不是经过观众实验校准的网感质量分。
自动节拍/镜头提取、人体轨迹识别及文字自动测量布局仍需独立分析能力。

## 候选搜索、回退与偏好校准

搜索保留有界候选前沿，优先覆盖尚未尝试的素材槽或策略，再用实际编译后的分数继续扩展。
同时尝试联合素材分配，避免多个空槽使所有单槽替换都失败。空视觉槽可从工程目录中发现
候选；显式绑定只使用传入的候选或模板声明的备用槽替换，停用槽不会被自动启用。
源入点、适配和焦点属于绑定的一部分。失败候选仍能继续扩展其他维度，结果包含
`search.coveredDimensions`、`unexploredDimensions`、`frontierRemaining` 和前沿截断标记。
候选执行预算最多 24，前沿最多 2048；达到预算时并不保证所有维度都已覆盖。

`POST /templates/repair` 使用相同 Evaluation 输入和真实编译器，返回可执行的
`selectedRequest` 与 `compilation`，不写工程。优先选择最终差异代价较低的可执行候选，
同代价时优先评分更高的方案，再按稳定候选 ID 排序。`repairCost.components` 给出明细：
每槽素材替换 1，布局策略改变 2，文字时长损失比例乘 12、其他视觉元素乘 6，
每条取消转场 8，其他模板替换 20。这些是透明的初始启发式代价，不代表已学习的用户偏好。
代价只比较原始请求与最终请求，撤销过的中间调整不重复收费；`changes` 仍保留搜索过程。
节奏、布局偏好、事件源采用字段级修改，互相组合时保留已有时长及转场修复。
`repair.shortenElements` 按元素 ID 指定允许缩短到的下限；只能缩短非声音元素，且
不得低于模板自身最短显示时间。`repair.cutTransitions` 按配对规则 ID 允许改为直接切换。
两者默认空，不擅自调整。显示缩短不会修改词时间、输入总时长或源音频时间。
工作台检查失败后调用该接口，用户仍需点击写入工程；写入前重新读取修订并编译。

`/evaluate` 保存本地评估回执，返回 `evaluationId`、`profileId` 和 `calibration`。
`POST /templates/preferences` 接收评估 ID、两个可执行候选 ID、理由和幂等键；分项只能
取自 Rust 保存的回执，不能由客户端上报。可选 `renderedPaths` 提供双方本机 PNG/JPEG/MP4
成片或帧文件，保存路径、大小和 SHA256。文件属于审阅者提供的证据，系统不宣称已验证其
与候选方案的对应关系。无文件的比较可以记录，但不用于成片评分训练。

各 `profileId` 独立保存偏好。至少 5 条分项不同的成片对比且跨 3 个输入才启用
`preference-v1`，使用正则化成对逻辑回归调整六项现有指标的正权重，因子限制在
0.25–4；用户显式设为 0 的权重仍为 0。此门槛是启用条件，不是统计有效性的证明，
它不学习像素、声音美学或新的质量维度。没有真实审阅数据时继续使用 `heuristic-v1`。
`GET /templates/preferences/{id}` 读取模型状态，`POST /templates/preferences/retract`
通过反馈 ID 和 `baseRevision` 撤销并重新拟合；历史反馈、模型版本保留，重复提交幂等。

## 句内关键词着色

`Treatment.operation = {"kind":"text_highlight","color":"#F44965"}` 是独立文字处理，
通过 `applications` 绑定到 `sentence` / `keyword` 文字元素或由这类文字组成的共享选择组。
它可与已有缩放、位移、描边、阴影和滤镜组合；不能当作画面滤镜应用到布局、图片或隔离合成组。
同一文字元素同时启用两个关键词着色规则会被拒绝，避免颜色依赖应用顺序。

Rust 将语义关键词的词范围与字幕显示单元求交，生成 `keywordRange` 的 UTF-16 半开区间；
使用生成整句的同一套拼接规则，重复词不会误选到第一次出现的位置。字幕换行由渲染器测量，
着色区间随换行映射，仍只绘制完整字形行，避免拆词破坏字距。没有关键词的句子保持基础填色。
默认 `mode:"keyword"` 为静态关键词填色；`mode:"active_word"` 对 `sentence` 文字按实测词起止
逐词切换颜色。两者支持从左到右的文字，不代表译文词对齐、词内连续扫色或富文本字号。

工程中保留整句可编辑文字，`text.highlightEnabled` 与 `text.highlightColor` 可单独修改。
原文及区间写入 `text.highlightRange`；人工修改文字后，旧区间自动失效，重新编译后再按新词范围生成。
`template_schema.capabilities.textHighlight` 暴露目标、方向、区间编码和编辑失效规则。

跟读模式把每个词的范围与真实起止时间编译为 `text.highlightRange` 的离散关键帧；
它与位置、缩放等通道并列，前端复用既有关键帧采样，不重新推算语速。词之间的停顿恢复
基础填色，提前入场部分不着色；字幕转场添加预滚时同步移动关键帧，保持实际发音时刻不变。
字幕延迟或截短时只裁切着色窗口，不改原词时间；没有可信词对齐的内容不能启用跟读模式。
