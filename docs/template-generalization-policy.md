# 模板泛化与 Agent 应用规则

2026-10-07。当前创作约定：以泛化为主，单个 case 由 Agent 调整。本文定义创作与验收边界，复用当前原生契约；不是新增运行时字段或自动识别能力。

## 模板交付什么

模板是一套有完整默认效果的视觉设计及适配规则。保存字体层级、配色、材质、图文依附、相对运动、内容绑定与事件生命周期。转场、滤镜、文字动效和装饰保持正交组合。声音事件决定实例时间；模板不保存某句台词、该句词下标、特定人物坐标或某次 TTS 的绝对秒数。

这里的可复用样式指 `dynamic_asset::Definition`。`model::Template` 是编排文档，允许携带本次生命周期事件 ID、场景转场与应用投影，因此保存 Template 不等于发布可复用样式。样式图、具体编排及能力范围的对应关系见 [结构所有权](template-ontology.md#结构所有权2026-10-09-核对)。

每款设计附带简短的应用说明：

| 项目 | 应说明的内容 |
| --- | --- |
| 用途 | 正文、重点词、情绪花字或图解；何种语义适合触发 |
| 风格不变量 | 必须保留的字体层级、色彩关系、轮廓、图文比例与运动特征 |
| 可调范围 | Agent 可调整的行宽、整体大小、位置、装饰密度、资源槽与事件策略，以及适用边界 |
| 阅读与构图约束 | 在目标画幅上的最小可读字号、最大行数、安全边距、重要画面保护和最低稳定展示要求 |
| 降级顺序 | 不能满足约束时，允许换位置、减装饰、换构图或换模板的次序 |
| 验证范围 | 已测语言、词长、背景、画幅与事件密度；未验证范围明确保留 |

独立样式现可通过 `definition.usageGuide` 保存上述六部分（`purpose`、`invariants`、`adjustments`、`constraints`、`fallback`、`coverage`）。每部分1–4000字符，可整体省略以兼容旧素材。工作台“应用规则→模板使用指南与来源”编辑，原生schema及读写工具暴露同一字段；保存进入新revision。它是Agent可读的创作指导，不是自动执行的数值约束引擎。

这些约束按设计用途确定，不把某款样式的24%行宽、40px字号或80ms入场当全库默认。未定义数值时，Agent根据输出画幅和阅读用途提出本次预算并记录，不冒称模板已有保证。

## Agent 负责具体应用

Agent读取保存版与当前能力契约，分析当前画面、声音、文案，选择适合的模板，然后在单次应用中调整。允许不同 case 使用不同参数，无需为了测试而强迫不同画面共用坐标。

| 层次 | 允许保存的内容 | 当前表达 |
| --- | --- | --- |
| 输入标注 | 重点词、语义短语、字幕段、人物/图示保护区、焦点 | `semanticUnits`、`layoutPhrases`、`captionSpans`、`protectedRegions`、`focalPoint` |
| 样式应用 | 画幅、候选位置、行宽、整体比例 | Application 的 `canvas`、`placement`、`transform`、`textWidths`、`captionWidth`；位置建议接口 |
| 本次编排/组合 | 与声音对应的生命周期、装饰取舍、资源替代、组合关系 | 当前 schema 支持的 timing、visualRhythm、资源与 composition 字段 |
| 模板版本 | 跨案例成立的视觉不变量和设计改进 | 显式保存新 revision；不能被应用调参隐式覆盖 |

实际字段所属对象以当前 schema 为准。Agent不能把文档中的建议字段直接发送给不支持的接口。修改 Application 投影之外的编排、样式或图层时，应保留为本次定制组合；它不能登记为未改变的原样式 Application 评审。如需复用该组合，另存并独立验收。

防遮挡首先执行[统一应用规则](template-placement-rule-20261009.md)：根据整个效果的空间占用和画面保护区搜索位置，优先最小像素位移，保持整组关系。保护区来自当前内容标注；规则和安全边距可复用，不为单个画面改模板默认坐标。完整包络缺失时只能给待验证方案；严格模式应等待证据，无法满足硬约束时跳过叠加或换构图。Agent 负责标注和补证据，不以逐例手调替代规则执行。

位置约束之外，再处理行宽/换行和尺度；装饰拥挤时减少或替换装饰。可在保持风格的前提下缩字，但不得低于该次阅读预算。短事件优先简化动作；延长视觉停留必须由明确事件/编排规则表达，不改造原声词时间。无适合语义时不触发图标。没有满足约束的方案时换构图或换模板，并记录失败原因，不硬塞、不靠任意缩小宣称成功。

人工判断、模型推断与测量结果分别记录；没有检测证据不得称自动识别。位置建议的几何通过不等于最终画面通过。变更文字、字体、宽度、比例或画幅后重新测量；用实际字号、行数及溢出结果检查阅读预算，查看稳定帧及完整入退场，音频是否试听单独记录。

## 什么时候改模板

- 单个画面空间特殊、词长不同或背景干扰：调整本次应用，保持模板版本。
- 多个不同输入暴露同类设计问题：提炼通用修正，更新模板并回测；例如装饰依附错误、图层退场不一致。
- 有独立证据证明底层契约错误：修复共享实现并加针对性回归，不等待多个坏案例，也不在样例里绕过。
- 风格身份已经变化：另存候选，不把它伪装成原模板的一次小幅调参。

禁止用输入 ID、原句、演员名或绝对秒数在模板/运行时代码里分支修补。Agent对具体输入作语义和构图判断是预期行为，保存输入标注与应用参数即可。

## 如何验证泛化

冻结模板版本、风格不变量和允许调整范围，在未参与设计调参的新输入上让 Agent 应用。泛化的目标是“同一风格与规则能被可靠应用”，不是“所有输入都使用相同参数”。

覆盖长短词、多行、快慢/密集事件、有无重点、不同明暗和复杂背景、关键人物/图示保护。声称支持其他语言或画幅时补相应样例。按当前生产与评审协议完成必要样例数量；数量本身不替代覆盖度。

每次保留：模板 ID/revision、输入版本、调整前后参数、调整原因、测量/成片证据、是否改动风格、未通过项。可在生产证据目录附 `adaptation.json` 作为 Agent 记录；这不是原生接口要求的新字段。区分直接使用、范围内调整、换模板和失败，评估效果质量及调整成本。自动检测能力另行验证。

测试中修改模板后，该输入成为开发样例；修正后回归旧样例，并继续用未参与修改的新输入验证，不能只对修好的 case 宣称泛化。原样式分数不能继承到不同位置、画幅或定制组合。单例调得漂亮不证明模板通用；模板字段齐全也不证明效果达标。

不同 Application 的跨输入验收使用 `qualityReviewSeries`：每个输入保留自己的应用、调整原因、分项评分和生产证据。系列以最差 case 的分数为准，所有 case 都必须满足门槛才达标；旧单应用评分不被替换，也不能把平均分或最高分当作泛化效果。接口与回读规则见[跨输入应用评审](style-review-protocol.md#跨输入应用评审)。

## 阅读时间与降级

画面空间通过后，仍要检查实际显示时长。`minDisplaySeconds` 是利用事件后空余时间的保持请求，受下一事件、显式结束锚点、最大时长及输入结尾约束，不保证一定能达到，也不修改声音或对齐词时间。以原生编译后的实例边界为准，扣除实际入退场及不可读阶段，再按当前文字、语言和阅读情境确定稳定阅读预算。预算属于具体内容应用；不能把某句的字数、语速或绝对秒数写成样式特判。

Agent 可在 `placement-advice.readingCheck.samples[].timing` 提交 `stableSeconds` 与 `requiredStableSeconds`，让 Rust 判断调用方提供的稳定阅读时间是否足够。任何一条不足都会拒绝位置方案；缺省或部分提供的时长证据不能作为完整时长通过。该接口不推断通用语速、不自行验证测量来源，也不证明连续观感或听感。

阅读证据同时提交 `readingCheck.scope:{application,sample}`，请求的 `application` 与 `sample` 必须和测量快照一致。旧数据没有 scope 时返回 `unscoped`，只供诊断，不参与本次阅读门控，也不能称作通过；有 scope 但已换内容或参数时直接拒绝。上述时长门控针对身份一致的证据。候选位置变化后返回 `requires_candidate_measurement` 并保留原检查的 `sourceStatus`，不能把原位置的测量通过继承到新位置。历史脚本保存的旧 reading-request 必须根据实际测量对象重新生成，不能为获取 passed 而给旧测量补填当前身份。

不足时依次判断：能否利用下一语义内容前的空余时间延长本次显示、能否选取语义完整且更短的重点、是否应取消该触发或换更简洁的样式。原文不适合提炼或输入尾部没有余量时允许跳过，保留原因与失败证据。不得通过伪造词时间、默默延长音轨或删去失败记录来满足预算。修改时长后重新检查后续事件、画面保护和入退场；修改动效或内容后重新提交稳定阅读证据。
