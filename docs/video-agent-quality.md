# 视频 Agent 质量改进

2026-10-26，针对此前评分发现的三个缺口：漏看叠加层、只生成证据没有判断、缺少声音节奏依据。

## 使用

在 **Codex** 智能剪辑中选择「导演」档，或开启完整复核。Codex 完整创作请求也会启用完整复核。
日常「均衡」档保持轻量版本检查，避免每次小改都增加模型调用。
已经运行中的常驻 MCP 进程需要重新连接 Agent 才会加载新代码；仅刷新编辑器不一定重启该进程。

1. 时间段识别同时查看源素材与最终合成画面，包含文字和叠加层。
2. 修改后运行结构检查，采样整条时间线，图片传回模型检查。
3. 明确问题可触发一次修正；随后重新采集新版本证据。仍有问题直接报告。
4. `analyze_audio` 提供起音和能量数据供选切点使用；不自动改变切点。

Claude Code 共用改进后的取帧和声音分析工具，并补充了先看合成画面、有限修正、
证据不足需报告的调用指引。宿主自动发起检查/修正 turn 的流程本轮只接入 Codex；
Claude 仍由模型执行这些工具步骤，不将两条通道描述为相同的自动化保证。

取帧、时间映射、节奏分析和复核结论校验在 Rust `moirai-agent-analysis` crate。
MCP、浏览器与 app-server 负责媒体解码、传输和会话执行。
开发环境首次调用会构建 Rust CLI；预构建环境可设置 `MOIRAI_AGENT_ANALYSIS_BIN`。

## 已验证的证据

- Rust 回归：同时出现的主轨/商品叠加轨、短标题、隐藏轨、变速曲线、倒放、定格、图片、采样预算。
- 音频：合成 120 BPM 脉冲经过实际 HTTP 媒体读取、FFmpeg、Rust 分析后返回约 0.5 秒的起音间隔；静音和持续音不生成 BPM。
- 会话协议测试：图片真正进入后续模型输入；一次修正后重新采集；重复问题停止；人工修改使证据过期；结构错误不能被模型的 pass 隐藏；取帧失败写入最终回复。
- 渲染测试与界面检查：后台取帧完成或失败后恢复当前播放头对应的预览画面，避免“播放头在开头、预览停在尾帧”的副作用。
- 真实品牌短视频测试工程 revision 2：内置浏览器返回 1/3/5/7/9/11 秒的合成联系表，字幕保留，另有三份源素材联系表。只读检查没有修改工程。
- 24 秒真实配乐得到 101 个起音候选；没有给出 BPM，保留估计不确定性。

相关回归共 111 项通过：Rust 12、MCP 15、Web 会话及传输 59、Claude 5、渲染/AgentManager 20。
Web 类型检查、变更文件 ESLint、Rust Clippy 和 `git diff --check` 通过。

证据位于 `artifacts/video-agent-20261026/`，其中 `evidence-2.jpg` 为合成画面，
`inspection.json` 和 `audio-analysis.json` 为去除图片数据后的检查记录。

## 验收边界

完整复核最多两次视觉检查和一次修正 turn，会增加模型调用和等待时间。
复核阶段通过指令要求模型只读，宿主会再次检查 revision；版本发生变化不能通过复核。
本轮验证了真实媒体/浏览器通道和模拟模型响应下的完整控制流程；尚未把新流程用于
五条真实商业任务及两轮创作者改稿。因此没有重新上调 Agent 的产品成熟度评分。

代表帧最多 12 个、选区合成采样最多 24 个、源素材组最多 12 组，遗漏明确报告。
它不能证明逐帧无异常、连续运动流畅、声音好听或文案达到商业投放标准。
能量起音也不等于音乐重拍；节奏分析最多读取前 600 秒。
