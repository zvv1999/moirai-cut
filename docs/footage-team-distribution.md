# 素材库团队分发流程

日期：2026-09-10。本文是团队部署方案；当前运行的是单机版本，不能通过分享 localhost 地址给其他人使用。

本地素材库是基础产品，不需要 NAS。默认本地模式支持上传、模型分析、打标、审核、本地入库和编辑器关联。NAS 是可选团队同步功能：开启后补同步已有原片和发布版本，以后本地入库时自动创建后台同步任务；失败可重试，不阻断本地使用。视频、封面、标签、使用限制和血缘 JSON 属于同一个固定发布版本，元数据最后同步。只有 NAS 同步完成的版本才可作为团队 NAS 上的可用版本；“本地已入库”和“NAS 已同步”是两个独立状态。下面流程中的团队发布指同步及团队服务授权均完成。

## 发布与使用

1. 上传者提交原片及产品/SKU、批次。原片归档完成后进入模型分析。
2. 审核者确认分镜区间、方向、画幅、标签与使用限制，提交加工。
3. 发布者预览加工结果，确认后发布。视频、封面、元数据写入 NAS 且校验成功，才将该发布版本标记为可分发。处理中或失败的版本不可下载。
4. 编辑人员在 Moirai Cut 的产品素材库中按 SKU、用途、描述检索，预览后选择“关联到工程”。默认显示当前已发布版本。
5. 工程导入对应版本的视频及元数据快照，本机保存副本；时间线通过工程媒体 ID 使用它。重复使用同一版本无需重复下载到同一工程。导出使用加工母版，720p 模型代理不用于成片。
6. 发布者后续修改内容或标签，会产生新的审核及发布版本。已存在工程继续绑定旧版，编辑人员收到更新提示后自行选择是否替换；替换需要检查入出点、时长、画幅与字幕，不允许后台静默替换。

“已入库”是发布状态，不是“文件已上传”的同义词。模型候选、加工待审、失败任务均不可进入团队默认分发列表。

## 部署与权限

推荐一台局域网常驻服务主机连接 NAS，托管 Rust 素材服务和 Web 入口，经 HTTPS 网关对团队开放。模型凭据、NAS 写入凭据和素材服务内部 token 只在服务端。团队成员通过统一账号登录，禁止在浏览器或下载链接中附带这些凭据。异地使用通过企业 VPN 或经过认证的网关。

| 角色 | 上传 | 修改候选/加工 | 发布/下架 | 使用已发布版本 |
| --- | --- | --- | --- | --- |
| 上传者 | 是 | 本人批次 | 否 | 按产品授权 |
| 审核者 | 是 | 授权产品 | 否 | 是 |
| 发布者 | 是 | 授权产品 | 是 | 是 |
| 编辑人员 | 可选 | 否 | 否 | 授权产品 |
| 服务账号 | 归档执行 | 任务执行 | 执行已批准任务 | 提供下载 |

API 同时校验角色和产品/项目范围，下载、预览、搜索都必须遵守相同权限，不能只隐藏界面按钮。第一版可由审核者兼任发布者，但保留独立审核事件及操作者 ID。

当前挂载位置是 NAS 账号的私有 `home` 共享，且 Web 代理仅允许本机。不能直接改成监听所有网卡来代替团队部署。上线时由 NAS 管理员分配专用共享目录及服务账号；原片限制访问，已发布片段可授予团队只读权限，所有写入走服务。推荐结构：

```text
moirai-library/
  inbox/<uploader>/<batch>/
  sources/<sourceId>/original.ext
  shots/<shotId>/r<revision>/master.mp4
  shots/<shotId>/r<revision>/poster.jpg
  metadata/<shotId>/<releaseId>.json
  collections/<collectionId>/<version>/manifest.json
  backups/
```

直接访问 SMB 只作为兼容方式。NAS 文件夹本身无法表达下架、权限变更和版本更新；正常工作流以认证后的素材服务目录为准，避免人工覆盖或重命名发布文件。

## 两种分发方式

**编辑器直接使用，默认方式。** 编辑器向素材服务请求发布清单及授权下载，校验 SHA-256，先下载到临时文件，完成后原子提交到本机工程媒体库。支持批量选择、有限并发和断点续传；本地按输出哈希缓存媒体，工程仍保存独立的版本引用和标签快照。NAS 离线时已缓存的工程可以继续剪辑，新下载显示重试状态。

**素材包，兼容其他剪辑软件。** 发布者创建指定产品/用途的素材合集，固定一组 releaseId，生成版本化清单、视频、封面及 CSV/JSON 标签。包内每项包含稳定 ID、文件名和 SHA-256；导出完成后才能提供下载。外部软件无法自动保留完整血缘时，以包清单为追溯依据，不把文件名当作唯一 ID。共享链接需要权限校验、有效期和撤销能力。

合集清单至少包含：`collectionId`、`version`、创建者、创建时间，以及每项的 `releaseId`、`shotId`、`shotRevision`、`sourceId`、源区间、输出哈希、相对文件名、标签、使用限制。合集增删成员生成新版本，不修改已分发清单。

## 版本、下架与通知

- 普通更新：旧版保持可追溯，服务提供 `supersededBy`，使用旧版的工程显示更新提示。
- 普通下架：禁止新导入，已存在工程保留其副本与版本信息，并显示下架原因。
- 严重错误或授权撤回：标记 `revoked`，列出受影响工程及责任人，要求替换并在新的在线导出前检查。已经交付或离线拷走的文件无法由服务器自动召回，需人工处置记录。
- 原片和发布母版禁止就地覆盖。只有无工程引用、超过保留期且备份验证通过的版本才进入独立清理流程。
- 发布、更新、下架事件在数据库事务中写入 outbox，再异步推送站内通知；通知失败不回滚已验证的发布。跨机器工程上报引用关系以 projectId/mediaId/releaseId 和工程 revision 幂等更新，并区分“当前使用”“历史使用”“设备离线未确认”，不能把心跳过期等同于没有引用。

## 上线验收

用两台机器及两个不同权限账号验证：审核前不可见、发布后可搜索下载、文件哈希一致、重开工程仍有血缘、旧版不被新版本替换、下架阻止新导入、非授权产品不可读取、NAS 中断可恢复、相同版本不会重复下载、跨机器引用记录可反查。验证数据库和 NAS 元数据/母版可一起恢复，备份恢复演练通过后再接正式团队。

当前已实现本机的审核发布、固定版本导入、工程副本和血缘快照、Agent 读取以及本机工程反查。团队登录/权限、跨机器引用汇总、版本通知、素材合集、断点续传与分发审计尚未实现，是下一阶段部署范围。现有私有目录不会自动变更为团队共享。
