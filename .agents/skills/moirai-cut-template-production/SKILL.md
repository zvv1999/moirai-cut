# Moirai Cut Template Production

目标是交付有设计差异、能适配实际内容的模板及成片证据。Agent 负责设计；Rust 负责素材版本、调度、编译、验证和批次状态。读取仓库的 `docs/agent-smart-edit.md` 和 `docs/template-production.md`，再调用 `template_schema` 获取当前执行能力及 `productionAuthoringInput`。

## 泛化优先，单次应用由 Agent 调整

设计或应用模板前，阅读 [模板泛化与 Agent 应用规则](../../../docs/template-generalization-policy.md)。模板保存完整视觉设计、风格不变量及适配边界；Agent根据当前输入调整位置、行宽、比例、内容标注和装饰取舍。允许不同case使用不同应用参数，不能把个案坐标、台词或词下标写回通用默认。单例效果仍需检查，泛化验证允许在已声明范围内调整，不要求所有样例同坐标。

先判断问题归属：内容/画面特有问题改应用；重复的设计缺陷才修订模板；共享契约错误修实现。定制组合保留单独证据，不继承原样式评分。冻结模板版本后，用未参与调参的新输入验证，记录调整原因、范围和失败结果；效果优先，不以字段数量或导出成功代替质量。

防遮挡按[统一位置规则](../../../docs/template-placement-rule-20261009.md)执行：先标注整段人物、产品、烧录字幕和其他叠加物的保护范围，再调用 `advise_dynamic_asset_placement`。默认由 Rust 从保护区几何求最近位置，不提交一套模板专用坐标代替搜索。需要完整避让结论时使用 `policy.requireFullCoverage=true`；缺动效包络或保护区覆盖声明就补证据，不能把静态建议记为通过。组缩放/旋转等使旧包络不能直接平移时，重新渲染候选。无解则跳过本次叠加或换构图，不改变模板默认位置、缩小到不可读或放宽真实保护区来凑通过。将规则、留白、保护区、返回原因与实际复核证据随本次应用记录保存。

需要记录或恢复具体输入的调整时，阅读[单次应用历史与恢复](../../../docs/template-application-history.md)，先从当前 `dynamic_asset_schema` 确认能力。为一次应用保持稳定contextId，先保存基线，后续保存完整应用与输入快照、理由和证据；沿原生head追加，冲突时保留编辑并复核。恢复先备份current，使用返回的下一父记录继续。记录保存不修改模板或项目，也不代表质量通过；实际工程回写仍走智能剪辑协议。

## 素材与声音

用 `list_template_inputs` / `read_template_input` 选择素材库输入，检查真实画面、原文和测得的词时间。没有素材时，可按用户目标导入本地素材，或用 `generate_template_speech` 创建配音并等待转写。输入 ID 与当前转写 revision 一起提交；修改文案需先用转写校正工具保留原始时间，不能根据字数伪造对齐。

非口播内容可以使用显式声音或时间事件，不必制造字幕。样例字段省略 `transcriptRevision` 时需提供 `events` 或 `soundEvents`，注明事件证据。文字语义段、字幕显示段、关键词范围分别建模。一个批次可用 1–8 个不同输入测试全部设计；优先选择内容长度、关键词长度或构图有差异的输入。

### 内容短语与样式复用

在设计样式之前，基于原文和当前对齐词审核 `layoutPhrases`。优先标注拆开后会破坏阅读的紧密短语，例如动词与补语、程度修饰与核心词、数量与量词、专名；根据句意判断，不维护针对示例句的替换表。不要把整句或全部关键词默认标成同排，不把普通相邻词一律合并。范围必须对应真实对齐词边界，不能为得到理想换行拆造时间词。标注范围跨字幕显示段时，先复核内容分段是否合理；不要延长声音或静默改写用户分段。

同一输入的短语标注在不同样式间复用。模板只决定字体、区域、行数和对齐方式；不保存该输入的词下标、不插入固定换行。用至少三组不同长度文案交叉检查多个样式，比较不标注与标注后的画面；短语放不下时允许正常回退，仍检查字号、孤行与遮挡。此步骤是 Agent 内容分析，不应描述为渲染器自动理解中文。合成示例验证后仍需实际音频和成片验收。

检查短语边缘的虚词与语法关系：只圈核心词可能留下行首“的”等生硬断点。根据实际句意将必要的助词纳入所属短语，再检查测量后的换行；不能仅凭元数据存在、短语未被拆开就通过视觉验收。标注与布局之间存在取舍时保留失败对比，说明还缺少什么，而不强行宣称通用通过。

图像/视频装饰先用 `list_template_assets` 检索，再按需用 `import_template_asset` 入库，保留来源。需要生成视觉素材时使用当前环境确实可用、已获授权的生成能力；不可把下载/截图/派生帧冒称为 AI 生成，也不可在生成能力不可用时谎报完成。声音从独立音效库检索，未试听的提取候选保持未确认；不自动将其作为合格音效绑定。

### 人物裁切与画面信息保留

选构图时先检查画面中的讲解图示、屏幕文字、产品、手势和其他人物，再决定是否裁切。`focalPoint`只控制画面焦点，不能证明重要信息完整保留，也不是人脸自动检测。人物占比更大不自动代表构图更好。

模板保存画面区域与容纳/裁切规则；焦点属于具体输入，不把某个演员的坐标固化为通用默认值。背景承担讲解作用（例如太阳图示）或标识需要完整展示时，优先使用完整画面版；单人表达为主且环境可舍弃时，再测试人物裁切版。若没有自动分析证据，明确注明Agent人工选择。

复用验收至少更换人物、背景明暗和标题长度，保持保存模板不变；同时检查有重点词和没有重点词的片段。无相关语义时不强加装饰。查看字幕代表帧及关键动作时刻，记录裁掉的环境/手势，不以人物面部仍在画面内作为唯一通过条件。

## 设计与批量提交

先检查相关参考视频或连续帧，提取构图、字体层级、强调时机、运动方向、换景节奏等可观察特征。参考并不提供原产品的可编辑模板结构；新设计应明确为重建或原创。

各设计在构图、文字层级、运动或编排上应有实际区别；仅改名字或换色不足以证明风格丰富。文字绑定到 title、sentence、keyword 等内容角色，素材使用资源槽。转场、滤镜和动效按当前正交能力契约组合，不能为某种字幕写一个不可复用的专用效果。

调用 `produce_templates`，传入：

- `idempotencyKey`、批次 `name` 和创作 `brief`。
- `designs`：完整模板及其库中 `baseRevision`，新模板为 0。
- `samples`：`inputId`、`transcriptRevision`、标题，以及需要的语义段、字幕段、翻译、资源绑定和人物焦点。

该工具自动创建独立的 `Template Production / ...` 工程、导入已校验的原片并提交生产。无需逐个 `create_project` 或组装 `CompileInput`。命令行等价入口是 `bun run templates:produce --designs /absolute/path/designs.json`。

同一内容的重试保留幂等键。准备中断时会复用原工程，批次已提交时返回原批次；工程被人工修改或输入损坏会拒绝覆盖。修改设计/样例则用新键创建新批次，已有模板更新时带当前版本。失败后先读具体错误，修复原因再重试；仍在运行的任务继续观察，不因一次超时重新创建。

## 成片检查与交付

轮询 `read_template_production`，直到 `renderJob` 终态并检查每项状态。成功需所有样例实际导出、校验并入库。`published` 仅表示技术检查通过，不能等同于审美合格。

从 `read_template_production_item` 获取预览和样例工程。检查每个设计的开头、稳定显示、运动/转场交界和结尾；覆盖长词、多行字幕和不同输入。检查人物焦点、字幕可读性、文字遮挡、连续原声及节奏。发现问题时按泛化规则区分输入适配与模板缺陷：前者调整本次应用并复测，后者修订模板后回归旧样例并验证新输入。单例参数不自动晋升为模板默认。

阅读检查同时包含空间和时间：从实际编译边界与入退场证据计算稳定阅读时长，通过 `placementAdvice.readingCheck.samples[].timing` 提交 `stableSeconds/requiredStableSeconds`。预算按具体文字和语言判断，不硬编码统一字速；缺省或部分时长证据不等同通过。`minDisplaySeconds` 可能受后续事件/显式边界/输入尾部截短，检查原生 warnings 与实际实例时长；不足则调整本次保持、提炼完整重点、跳过或换样式，不改造对齐词时间或延长声音。修改内容、时长或动效后重新测量。

不同输入采用不同 Application 时，通过 `dynamic_asset_schema.qualityReviewSeries` 和 `review_dynamic_asset_series` 保存跨输入评审。每个 case 保留完整 Application、对应生产项的所有成片证据与调整原因，整个系列至少三份不同成片；原单应用评审仍要求同一应用的至少三份成片。系列分数取最差 case，所有 case 的内部门槛、试听与最终审美标记分别合取。背景和语义覆盖必须真实检查，不能用不同哈希冒充不同输入。回读 `current/evidenceCurrent` 后再引用评审，模板与工程不随评审改变。

给用户批次名称、设计数与实际成片数、预览入口、可编辑工程位置和仍未验证的范围。只有对照过参考并查看成片后才能描述相似程度；不要用编译分数声称达到开拍同等质量。
