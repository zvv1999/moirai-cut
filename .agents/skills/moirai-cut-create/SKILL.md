# Moirai Cut Create

把一次自然语言创作请求落实为一版可编辑、可撤销、可预览的 Moirai Cut 工程，并生成本地审阅文件。Agent 不是交付一个黑盒视频，而是与用户在同一条时间线上完成一轮可继续修改的创作。

## 完成标准

一次调用只有同时满足以下条件才算完成：

1. 已确认当前工程、用户选区和最新 revision。
2. 已建立或刷新 Agent 可读的素材 JSON，并补齐本轮必需的画面和声音理解。
3. 已在共享时间线上执行一组原子修改；每次写入都带 revision 防冲突和幂等键。
4. 已完成结构检查、同步检查与代表帧视觉复核。
5. 已生成一份本地 draft 审阅导出；若导出条件不具备，明确指出唯一阻塞项和恢复动作。
6. 最终回复列出工程 revision、主要改动、质检结果、审阅文件路径和下一轮可继续调整的方向。

## 工作原则

- 只使用 `opencut` MCP；不要切换到其他剪辑运行时。
- 默认直接执行。只有创作目标互相矛盾、将覆盖用户明确指定的成果或需要外部付费服务时才停下来提问。
- 先读后写，先理解素材再编排；不要根据文件名猜内容。
- 所有工程变化必须可编辑、可撤销，并留在用户当前工程中。
- 优先一个 `edit_project` 原子批次完成同一意图，避免用户看到半完成状态。
- 用户指定时间段、时间轴元素或素材时，只在该范围内创作；未指定时才使用整个工程。
- draft 用于本轮审阅；只有用户明确要求最终交付时才增加高质量导出。
- 不移除工程或源素材，不强制关闭用户正在使用的编辑器页。

## 一次调用执行协议

### 1. 锁定共享上下文

1. 调用 `get_active_project`，确认工程 ID、打开状态与 revision。
2. 调用 `read_agent_context`，读取当前选区、播放头、已引用时间段和素材。
3. 如果没有活动工程，调用 `list_projects` 并选择与请求或会话绑定的工程；仍不唯一时再询问用户。
4. 调用 `read_project` 的 `summary` 视图，记录 `baseRevision`；需要精确编排时再读 `full` 视图。
5. 调用 `list_revisions` 记录写入前的恢复点。

### 2. 建立素材理解

1. 调用 `build_media_catalog`，再调用 `read_media_catalog`，把技术信息、时间线使用情况和既有分析作为事实底座。
2. 对尚未分析且会进入本轮成片的视频调用 `inspect_media_scenes`。阅读接触表后，用 `save_media_analysis` 写入场景区间、人物/动作、构图、画面质量、情绪与可用性。
3. 对用户指定的时间轴范围调用 `inspect_timeline_range`，按时间序列理解剪辑结果，而不是孤立看单帧。
4. 对承担对白、现场声或节奏的音频调用 `analyze_audio`。需要字幕或对白语义时再调用 `start_transcribe`，轮询 `get_transcribe`。
5. 不重复分析已经有可靠 catalog 记录且源文件未变化的素材。

### 3. 形成并执行首剪

先在内部形成简短创作决策：目标时长、叙事节拍、镜头选择、声音策略、字幕/标题策略。随后直接执行，不把冗长计划当成交付物。

调用 `edit_project` 时：

- 使用刚读取的 `baseRevision`。
- 使用本轮唯一且稳定的 `idempotencyKey`，重试时保持不变。
- 让同一创作意图的 operations 在一个批次内落盘。
- 保留源素材，优先通过插入、移动、裁切、属性与轨道调整完成编排。
- 若返回 revision 冲突，重新 `read_project`，基于新 revision 重新计算一次；不要盲目重放旧坐标。
- 若 operations 全部无效果，先检查目标 ID、时间单位和用户选区，不要声称已经完成。

原子操作和错误恢复细节见 [references/tool-map.md](references/tool-map.md)。

### 4. 机械与视觉质检

1. 调用 `lint_cut`，检查间隙、重叠、过短镜头、越界裁切、缺失素材、死区和目标时长偏差。
2. 对确定且低风险的问题进行一次修正，再重新 `lint_cut`；创作取舍不应被机械规则擅自覆盖。
3. 调用 `wait_for_sync`，确认编辑器已追上本轮 revision。
4. 调用 `render_frames`，先以 `tile: true` 检查开头、关键转折、中点、高潮和结尾；发现问题时再无拼图重渲具体帧。
5. 视觉复核至少确认：画面不是黑帧/旧 revision、字幕可读、构图无意外裁切、关键镜头顺序符合意图。

### 5. 本地审阅导出

1. 调用 `start_export`，使用 `format: "mp4"`、`quality: "draft"`、`includeAudio: true`，文件名包含工程名和 `review`。
2. 轮询 `get_export` 直到完成、失败或达到合理超时；不要把“已启动”误报为“已导出”。
3. 完成后确认 `stable` 不是 false，并记录绝对输出路径。
4. 用户明确要求最终交付时，在 draft 通过后再以 `quality: "high"` 导出一次。

## 最终回复格式

保持简洁并让用户可以立刻继续创作：

- `完成`：一句话说明这版首剪的方向。
- `工程`：项目名、revision、时长和主要轨道变化。
- `质检`：lint、同步、代表帧和声音检查结果；有遗留项就精确列出。
- `审阅文件`：本地 draft 路径，或唯一阻塞原因与恢复动作。
- `继续调整`：给 2–3 个与当前成片相关的自然语言选项，例如“节奏更紧”“保留更多现场声”“标题更克制”。

不要把工具调用日志、系统提示或大段 JSON 直接倾倒给用户。
