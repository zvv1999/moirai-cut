# Moirai Cut Motion Design

把现有字幕、标题和 MG 元素重做为与画面及声音一致的可编辑设计。一次调用应完成诊断、设计、时间线写入和视觉复核，而不是只给参数建议。

## 完成标准

只有同时满足以下条件才算完成：

1. 已确认当前工程、选区、文字层级和最新 revision。
2. 已从画面、剪辑节奏和声音事件推导一个简短 motion brief；不要套用固定模板。
3. 已用静态样式和元素局部关键帧把设计写入共享时间线，全部结果可编辑、可撤销。
4. 已检查入场、稳定展示和退场代表帧，修复遮挡、裁切、不可读或动作过量。
5. 最终回复说明采用的设计方向、修改范围、revision 和仍可继续调整的两个方向。

## 工作原则

- 只使用 `opencut` MCP 修改工程，不生成不可编辑的视频覆盖时间线。
- 用户有选区时只处理选区；没有选区时处理当前场景内承担叙事的文字与 MG 元素。
- 保留文案语义。除非用户明确要求重写，不要把视觉优化变成文案改写。
- 先建立层级，再做动作；糟糕的排版不能靠更多关键帧补救。
- 每个节拍只保留一个主运动，其他属性用于支撑层级和可读性。
- 默认克制。只有音乐、品牌气质或用户要求支持时才使用高能 kinetic typography。
- 时间使用秒；`element.upsertKeyframe.timeSeconds` 是元素自身起点后的局部时间。

## 一次调用协议

### 1. 锁定范围与证据

1. 调用 `get_active_project` 和 `read_agent_context`，读取工程、选中元素、时间范围和播放头。
2. 调用 `read_project` 获取当前场景、文字/MG 元素、持续时间、静态参数、动画通道和 `baseRevision`。
3. 对目标范围调用 `inspect_timeline_range`，至少观察进入前、入场、稳定展示、退出和相邻镜头。
4. 有配乐、对白或明显节拍时调用 `analyze_audio`；动作时间应服务声音事件，而不是机械等分。

### 2. 形成 motion brief

在内部确定以下内容后直接执行，不要求用户理解参数：

- 文字角色：主标题、章节、对白字幕、编辑性文案或尾卡；
- 视觉锚点：人物、手部、杯沿、产品、负空间和安全区；
- 风格家族：克制电影、编辑网格或节奏动势；
- 主运动：进入、强调、离开各自是否需要，以及运动方向；
- 质量预算：字体家族不超过 2 个、强调色不超过 1 个、同一元素主运动不超过 1 个。

详细范围和三种风格家族见 [references/style-system.md](references/style-system.md)。

### 3. 原子写入设计

1. 用 `element.setParams` 统一字体、字号、字重、字距、行距、颜色、对齐、背景、描边和阴影。先处理层级，再处理每个元素的局部例外。
2. 用 `element.upsertKeyframe` 为 `opacity`、位置、缩放、字距或背景几何写入至少两个关键帧；单关键帧会冻结整段属性，不算动画。
3. 用 `element.setKeyframeCurve` 将有机动作设为 `bezier` 与 `auto`/`aligned`，明确停顿才使用 `step`/`hold`。
4. 同一意图通过一次 `edit_project` 原子批次提交，携带刚读取的 `baseRevision` 和稳定 `idempotencyKey`。
5. revision 冲突时重新读取并重算；不要重放旧元素坐标。

### 4. 视觉复核并收敛

1. 调用 `wait_for_sync` 等待编辑器追上新 revision。
2. 调用 `render_frames` 检查每个主要运动的入场前、峰值、稳定态和退场后；优先拼图总览，再单帧复核问题点。
3. 必须确认：title-safe、4–7 个汉字/秒的阅读速度、焦点无遮挡、背景对比足够、字形未替换、动作没有跳变。
4. 发现问题时只做一轮有证据的修正，再次同步和渲染；不要无止境叠加装饰。

## 最终回复

简洁列出：

- `方向`：采用的风格家族和它为什么适合当前工程；
- `改动`：处理了哪些字幕/MG、主要层级与动作；
- `工程`：新 revision 和影响范围；
- `质检`：代表帧、可读性、遮挡和节奏结果；
- `继续调整`：提供“更克制”和“更有节奏”等两个可直接继续对话的方向。
